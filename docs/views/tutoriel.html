Introduction

Ollin is a minimal, expressive scripting language: dynamically typed, compiled, and designed to be embedded.

A first program

print("hello world!")

Truth rules (true/false)

One principle: the empty is false. A value is false when it stands for absence or emptiness (nil, false, zero, an empty string, map or array); everything else is true.

ValueFalse when
nilalways
boolfalse
integer== 0
float== 0.0
stringthe empty string ""
mapempty {}
arrayempty []
assert(1 <> true)   ## distinct types: the boolean is sealed
assert(not 0)        ## zero => false, without being equal to false
assert("not empty")  ## a non-empty string => true
assert(not "")      ## an empty string => false

The two rules are independent, and both hold at once: zero is false (the empty is false), and yet zero is not false (the types do not mix). In other words, if x and if not x tell the truth of a value whatever its type — that is how a test is written — whereas x == false only holds for a genuine boolean. There is no bool(v) conversion: not not v does the job.

Arithmetic on the numeric types

Two integers combined give an integer — except for division /, which always gives a float. As soon as a float takes part in the computation, the result is a float.
assert(7 / 2 == 3.5)  ## division => always a float
assert(7 % 2 == 1)    ## modulo => int when both are ints

Variables

Every variable must be declared before use — using or assigning an undeclared name is a compile error.

var creates a variable local to the current function; global creates a global variable visible throughout the program.

Naming

A name starts with a letter or an underscore, followed by letters, digits or underscores (_counter, x1, final_score). It is case sensitive (score ≠ Score), and accented letters are not supported. The language's keywords (var, if, end…) cannot serve as names.

var a = 10
var b = 2.5
var s = "hello"
var undef  ## no initialisation => nil
assert(undef == nil)

Multiple declaration

var x, y = 1, 2
var p, q, r = 10, 20  ## r => nil (not enough values)

Assignment

var a = 10
a = 42  ## plain
a += 1  ## compound: += -= *= /= %=
a *= 2
assert(a == 86)
Underscores in numeric literals are ignored: 1_000_000 == 1000000.

Global variables — global

The global keyword declares a global variable, visible throughout the program. It can be declared anywhere, and read or changed from any function. A local variable (var) of the same name hides the global from its declaration onwards: before that line the name still means the global, so var x = x initialises from the outer value.

global counter = 0

func incr()
    counter += 1  ## changes the global from a function
end

incr()
incr()
assert(counter == 2)
print(counter)    ## 2
var always creates a local variable; global creates a global one, visible everywhere. Assigning an undeclared name remains a compile error.

Constants — const

The const keyword declares an immutable local. Initialisation is mandatory. Any later attempt to assign to it is a compile error.

const PI = 3.14159
const MAX = 100

assert(PI == 3.14159)
assert(MAX == 100)

func area(r)
    const TWO_PI = 2 * PI
    return TWO_PI * r * r
end

print(area(1))  ## 6.28318…
The following errors are caught at compile time: 
const x  ## ERROR: must be initialized
const x = 1
x = 2    ## ERROR: cannot assign to const 'x'

Bitwise operators

The bitwise operators work on integers only. ~ is XOR as a binary operator and NOT as a unary one; ^ is reserved for the power.

Binary

~ is XOR between two operands (a ~ b) and NOT as a prefix (~a). ^ is not a bitwise operator: it is the power (see Operators).

Precedence

From the lowest to the highest:

or  =>  and  =>  |  =>  ~(xor)  =>  &  =>  comparisons  =>  << >>  =>  + -  =>  * / %  =>  ~(not) - not  =>  ^

Examples

var flags = 0
flags = flags | 1         ## turn bit 0 on
flags = flags | 4         ## turn bit 2 on
assert(flags == 5)        ## 0101

assert((flags & 1) == 1)  ## test bit 0
assert((flags & 2) == 0)  ## bit 1 is not set

flags = flags ~ 1         ## XOR: flip bit 0 => 4
assert(flags == 4)

assert(1 << 8 == 256)
assert(256 >> 4 == 16)
assert(~0 == -1)
assert(255 & 15 == 15)
The bitwise operators need integer operands. Applying &, |, ~, << or >> to a float raises an error at run time.

Strings

var s = "hello"
assert(s == "hello")
assert(not "")   ## an empty string is false
assert("text")  ## a non-empty one is true

Concatenation uses +:

var greeting = "Hello, " + "world" + "!"
assert(greeting == "Hello, world!")
Strings are immutable. Only + is overloaded for strings — the other operators (-, *…) stay reserved for numbers.

Interpolation

Any expression in braces {…} is evaluated and inserted. \{ inserts a literal brace.

var name = "Ada"
var n = 42
assert("Hello {name}, n={n}" == "Hello Ada, n=42")
assert("result: {n * 2 + 1}" == "result: 85")

An optional format follows a : — a C conversion specification, without the %: .3f (precision), 04x (width plus zeros), -8s (left aligned)…

assert("pi = {3.14159:.2f}" == "pi = 3.14")
assert("hex = {(255):04x}" == "hex = 00ff")
assert("pad = [{n:5d}]" == "pad = [   42]")
An empty {}, or an integer ({1}, {2:.2f} — indexed from 1), is a positional placeholder left as it is: it is filled by printf's arguments (see Builtins), not by interpolation. Both sides share the same formatting engine.

Multi-line expressions

Line breaks are treated as whitespace — an expression may span as many lines as needed, with no special syntax.

var total =
    net_price
    * ((1 + vat) / 100)
    + shipping

if order_valid
    and in_stock
    and payment_ok then
    ship()
end
then, do and end delimit the blocks — brackets around a condition are never required.

If / Else

if condition then
    ## the then block
elseif other_condition then
    ## elseif (as many as needed)
else
    ## an optional else
end
var score = 75
var grade = "F"

if score >= 90 then
    grade = "A"
elseif score >= 80 then
    grade = "B"
elseif score >= 70 then
    grade = "C"
else
    grade = "F"
end

assert(grade == "C")
print(grade)  ## C
To chain conditions, use elseif. There is no "else if" sugar: an else followed by an if is an else branch containing a nested if block, with an end of its own.

While

var i = 0
while i < 10 do
    i += 1
end
assert(i == 10)

## break leaves the loop at once
var k = 0
while true do
    k += 1
    if k >= 5 then break end
end
assert(k == 5)

For

Two forms for numeric loops: by interval (for i in [a;b]) or by explicit bounds (for i=a,b). For iterating over maps and arrays, see Iterating over a map and Arrays.

Range [a;b]

Mathematical interval notation — inclusive or exclusive bounds, with an optional step.

var sum = 0
for i in [1;10] do
    sum += i
end
assert(sum == 55)  ## 1+2+…+10 (inclusive on both sides)

## right-exclusive: 1,2,...,9
for i in [1;10[ do
    print(i)
end

## with a step: 1,3,5,7,9
for i in [1;10;2] do
    print(i)
end

## first class: it can be held in a variable
var r = [1;5]
for i in r do
    print(i)       ## 1 2 3 4 5
end

Numeric i=start,end[,step]

The step is optional — positive or negative.

## the implicit step is 1
for i=1,5 do
    print(i)  ## 1 2 3 4 5
end

## a positive step (even numbers)
for i=0,10,2 do
    print(i)  ## 0 2 4 6 8 10
end

## a negative step (counting down)
for i=5,1,-1 do
    print(i)  ## 5 4 3 2 1
end

Break inside a for

for i in [1;100] do
    if i > 3 then break end
    print(i)  ## 1 2 3
end

Switch

switch compares an expression against several values. Each branch starts with case followed by one or more comma-separated values. The else block runs when no case matches. break is allowed inside.

var x = 2
switch x
case 1
    print("one")
case 2, 3
    print("two or three")
else
    print("other")
end

Switch on strings

var cmd = "start"
switch cmd
case "start", "go"
    print("starting")
case "stop"
    print("stopping")
else
    print("unknown command")
end

The do … end block

A do … end block creates a local lexical scope: variables declared inside are not visible after end. It is handy for isolating temporaries without writing a function.

var x = 0
do
    var tmp = 42
    x = tmp + 1
end
## tmp no longer exists here
assert(x == 43)

Closures created inside capture the block's variables as usual:

var fns = []
do
    var i = 99
    fns.push(func() return i end)
end
assert(fns[1]() == 99)
do blocks nest freely. A variable of an outer scope stays reachable inside an inner block.

Functions

func add(a, b)
    return a + b
end

assert(add(3, 4) == 7)

A function on a map field

func obj.field(...) defines a function straight onto a field of a map or a module — sugar for obj.field = func(...) ... end. Handy for the engine hooks (keyboard.keypressed, for instance).

var obj = {}
func obj.greet(name)
    return "greet " + name
end
assert(obj.greet("ollin") == "greet ollin")

Multiple returns

func minmax(a, b)
    if a < b then
        return a, b
    end
    return b, a
end

var lo, hi = minmax(7, 3)
assert(lo == 3 and hi == 7)

Recursion

func fact(n)
    if n < 2 then return 1 end
    return n * fact(n - 1)
end

assert(fact(10) == 3628800)

Optional call — f?()

The syntax f?(args) is exactly sugar for if f then f(args) else nil:

  • f false (nil, 0, "", [], {}) → no call, the result is nil, and the arguments are not evaluated, so there is no side effect;
  • f callable → an ordinary call;
  • f true but not callable (an integer, a string…) → a run-time error, as for an ordinary call.

The typical use is an optional callback (nil → skipped, with nothing run). It applies to every form of call, methods included (obj.m?() injects self; a missing method gives nil) and super.m?(). In the implementation it is a plain JUMP_IF_FALSE followed by the standard call — there is no dedicated opcode.

func greet() return "hello" end
assert(greet?() == "hello")  ## callable => an ordinary call

var cb = nil
assert(cb?() == nil)         ## nil => no call, and no error

## an optional callback plus an optional method call (self injected)
class Box
    func init(v) self.v = v end
    func get() return self.v end
end
var b = Box(7)
assert(b.get?() == 7)        ## self injected
assert(b.missing?() == nil)  ## a missing method => nil
A true value that is not callable is still an error: (42)?() raises "call on non-function value" (42 being true, the call is attempted). Only false values are skipped. The ? acts on the call immediately to its left, and on nothing else.

Variadic arguments

... captures every extra argument.

func log(level, ...)
    printf("[{}] ", level)
    print(...)
end

log("INFO", "starting", "ok")  ## [INFO] starting ok

Passing the varargs on to another function

func wrapper(a, ...)
    return a, ...  ## passes the varargs on
end

var x, y, z = wrapper(1, 2, 3)
assert(x == 1 and y == 2 and z == 3)

In the last position of a list, ... expands to all the varargs: as a call argument (f(a, ...)), an array element ([x, ...]), a return (return a, ...) or a multiple assignment (var a, b = ...). A call in last position likewise expands to all its values (f(g()), return g(), [x, g()]). Anywhere else the expression is trimmed to a single value (... → the first argument, or nil).

Default parameters

A default value must be a literal constant.

func greet(name, greeting="Hello")
    printf("{}, {}!", greeting, name)
end

greet("Alice")         ## Hello, Alice!
greet("Bob", "Hi")     ## Hi, Bob!
func connect(host="localhost", port=8080, debug=false)
    printf("{}:{} debug={}", host, port, debug)
end

connect()                    ## localhost:8080 debug=0
connect("prod.example.com")  ## prod.example.com:8080 debug=0
connect("prod", 443)         ## prod:443 debug=0

Closures

A function can capture the variables of the scope around it. The captured value stays alive even after the outer function has returned.

An encapsulated counter

func make_counter()
    var n = 0
    func inc()
        n += 1
        return n
    end
    return inc
end

var c1 = make_counter()
var c2 = make_counter()  ## independent state

assert(c1() == 1)
assert(c1() == 2)
assert(c2() == 1)        ## c2 starts again from 0

Closures created in a loop

Every iteration has variables of its own: a function created in the body captures the loop variable and the body's locals as they were on its pass, not their final value.

var fns = []
for i = 1, 3 do
    var square = i * i
    fns.push(func() return i + square end)
end

assert(fns[1]() == 2)     ## 1 + 1
assert(fns[2]() == 6)     ## 2 + 4
assert(fns[3]() == 12)    ## 3 + 9

Two functions created on the same pass, on the other hand, do share the variable — which is what makes the reader/writer pair of the "Shared state" section below possible.

A function factory

func make_adder(x)
    func add(y)
        return x + y
    end
    return add
end

var add5  = make_adder(5)
var add10 = make_adder(10)

assert(add5(3)  == 8)
assert(add10(3) == 13)

Nested functions

A function declared inside another stays local — it is not added to the global environment.

func process(data)
    func helper(x)        ## visible inside process only
        return x * 2
    end
    return helper(data) + helper(data + 1)
end

assert(process(3) == 14)  ## 3*2 + 4*2

State shared between functions

func make_shared()
    var count = 0
    func inc()  count += 1  end
    func get()  return count  end
    return inc, get
end

var inc, get = make_shared()
inc()
inc()
inc()
assert(get() == 3)
print(get())  ## 3

Maps

A key→value dictionary. The literal syntax accepts strings, identifiers, or computed keys [expr]; at run time any value can serve as a key (nil, an integer, a float, a string, a bool, an array, a map, a function…).

Creating one

var empty = {}

var point = {"x": 10, "y": 20}

## keys without quotes
var config = {
    host:  "localhost",
    port:  8080,
    debug: false,
}

Literal keys and computed keys

A key written as an identifier, as a string, or in brackets around a string is the same literal key:

var a = {ref: 12}      ## the key is the string "ref"
var b = {"ref": 12}    ## the same
var c = {["ref"]: 12}  ## the same

In brackets, an expression is evaluated at run time and its value becomes the key:

var ref = "color"
var m = {[ref]: "red"}     ## the key is ref's value => "color"
assert(m["color"] == "red")
assert(m["ref"]     == nil)  ## the literal "ref" is NOT a key

## a computed key can be of any type
var n = {[1 + 1]: "two"}
assert(n[2] == "two")

The same rule holds for access: in brackets, a string literal names the key as it is, while a variable names its value. Reading, writing and compound assignment all behave the same:

var ref = "color"
var m = {}
m[ref]     = "red"              ## writes the "color" slot (ref's value)
m["size"] = 10                  ## writes the "size" slot (a literal)
assert(m["color"] == "red")   ## read back through a literal
assert(m.color     == "red")  ## or through a dot
m["size"] += 5
assert(m["size"] == 15)

Reading

Brackets
point["x"]  ## 10
point["z"]  ## nil
Dot (the same)
point.x  ## 10
point.z  ## nil

Writing

var point = {"x": 10, "y": 20}
point["z"] = 0   ## a new key
point.z = 5      ## the same

point["x"] += 1  ## compound through brackets
point.y *= 2     ## compound through a dot

assert(point.x == 11)
assert(point.y == 40)

Nested maps

var scene = {
    camera: {fov: 60, near: 0.1, far: 1000},
    light:  {x: 0, y: 10, z: 0, intensity: 1},
}

assert(scene["camera"]["fov"] == 60)

Keys of any type (through brackets)

var m = {}

m[nil]   = "nil key"
m[42]    = "int key"
m[3.14]  = "float key"
m[true]  = "bool key"

## 1 and 1.0 are the same key
m[1] = "one"
assert(m[1.0] == "one")

Copy semantics

Maps are shared by reference, with reference counting. Assigning a map to another variable does not clone it.
var a = {x: 1}
var b = a          ## b points at the same map
b.x = 99
assert(a.x == 99)  ## a changes too
A consequence: == compares maps by reference and not by content — {} == {} is 0. For equality by value, see Equality and comparison.

Iterating over a map

The form for k, v in m walks every entry of the map. The order is not guaranteed.

var scores = {Alice: 95, Bob: 82, Carol: 78}

for name, score in scores do
    printf("{} => {}", name, score)
end
## Alice => 95
## Bob => 82
## Carol => 78

Summing the values

var scores = {Alice: 95, Bob: 82, Carol: 78}
var total = 0
for k, v in scores do
    total += v
end
printf("average: {}", total / 3)

Inside a function

func sum_values(m)
    var s = 0
    for k, v in m do
        s += v
    end
    return s
end

var scores = {Alice: 95, Bob: 82, Carol: 78}
assert(sum_values(scores) == 255)

Enum

enum declares named constants. The result is a frozen map: it can be read, iterated and measured like any map, but every write is refused.

enum Tint RED, GREEN, BLUE end
print(Tint.RED, Tint.GREEN, Tint.BLUE)   ## 1 2 3

Numbering

An element with no value takes the counter, which starts at 1 and advances by one. An integer literal sets the value and restarts the counter just after it. Any other expression is accepted as a value but leaves the counter where it is — the compiler cannot evaluate a function call.

enum State IDLE = 0, WALK, JUMP = 10, FALL end
## 0, 1, 10, 11

enum Mixed A, B = "text", C end
## 1, "text", 2 — the string does not move the counter
A corollary: A = 1 + 1 is an expression and not a literal, so it does not move the counter even though it comes to two.

Values of any type

A value may be a number, a string, an object, an array or a function. Two elements with the same value are an alias, which is allowed; two elements with the same name are a compile error.

enum Palette RED = Color(1, 0, 0), GREEN = Color(0, 1, 0) end

Immutability

Writing into an enum fails. When the target is visibly the enumeration, the error comes at compile time and names the element; the indirect paths — an alias, a computed key — are stopped at run time.

Tint.RED = 5        ## a compile error: cannot modify enum 'Tint' element 'RED'

var m = Tint
m.RED = 5              ## a run-time error: cannot modify an enum
The freeze is shallow: it protects the enumeration, not what it holds. If an element is an array or an object, that array or object stays mutable — E.L[1] = 9 goes through. Freezing deeply would make immutable an object that may be referenced elsewhere.

The target

A simple name declares a global, as a class does: forward references work. A path writes into an existing map.

global cfg = {}
enum cfg.mode FULLSCREEN, WINDOWED end
print(cfg.mode.FULLSCREEN)      ## 1

References

ref x gives a function the means to read and write the variable x, instead of receiving a copy of it. That is what lets a module keep a variable up to date — the typical case being a checkbox bound to a setting.

global grid = true
ui.checkbox("Grid", ref grid)

func draw()
    if grid then          ## an ORDINARY read: ref changes nothing about using the variable
        drawGrid()
    end
end
The point to keep: the variable stays a variable. ref only passes on the right to write it; the code that uses it does not change.

Handling a reference you receive

A function that receives a reference reads it with get() and writes it with set(v).

func toggleIt(r)
    r.set(not r.get())
end

global active = false
toggleIt(ref active)
assert(active)

Accepted targets

A name — global or local — or a path of fields. The name must be declared: ref unknown is a compile error, which is the whole point compared with passing a name as a string.

ref counter           ## a global or a local
ref cfg.tiles         ## a field
ref cfg.render.shadows   ## a path of fields
ref t[1]              ## REFUSED: the path would be re-evaluated on every access

Two limits worth knowing

A reference taken on a variable local to a block stays readable after leaving the block, but writing reaches nothing any more: the variable is gone, and the reference has closed over a copy.

Every ref x evaluated creates two closures and an object. That is negligible when declaring a widget, and to be avoided in a tight loop.

Error handling

Ollin uses try / catch / else / end. The else block runs when no exception is raised. Every block is optional.

try
    throw "something went wrong"
catch err
    print("error:", err)
else
    print("all went well")
end

Throwing any type

func divide(a, b)
    if b == 0 then
        throw {code: 42, msg: "division by zero"}
    end
    return a / b
end

try
    var r = divide(10, 0)
catch e
    printf("error {}: {}", e["code"], e["msg"])
end

A try with no body

try
catch err
    print(err)
end

Built-in functions

print

Prints every argument, separated by spaces, followed by a newline.

print("a =", 42, true)  ## a = 42 true
print()                 ## an empty line

printf

Positional substitution (indexed from 1, as arrays are): {} (automatic index, starting at 1) or {n} (an explicit index, {1} being the first argument), with an optional format {n:spec}, the same spec as in interpolation.

Import

The import statement loads an Ollin file and makes its content available in the current program.

Paths are relative to the current script's directory. The .ol extension is added when it is missing.

A flat import

Every definition of the imported file becomes available directly in the current scope.

## utils.ol
func add(a, b)
    return a + b
end
var PI = 3.14159

## main.ol
import "utils"
print(add(2, 3))  ## 5
print(PI)         ## 3.14159

A modular import

With as name, every definition is gathered into a named map.

import "utils" as math
print(math.add(10, 20))  ## 30
print(math.PI)           ## 3.14159

Rules

  • Paths are resolved relative to the current script's directory, recursively for nested imports.
  • Circular imports are detected and ignored, through a shared cache.
  • A file imported twice is executed only once.

Classes

Ollin supports object orientation with single inheritance, an implicit constructor and meta-methods.

Declaration

class Animal
    func init(name, sound)
        self.name = name
        self.sound = sound
    end
    func speak()
        return self.name + " says " + self.sound
    end
    func __str()
        return "Animal(" + self.name + ")"
    end
end

var a = Animal("Rex", "Woof")
print(a)            ## Animal(Rex)   — the instance is printed through __str
print(a.speak())    ## Rex says Woof
  • func init(...) is the constructor; self is passed implicitly as the first parameter.
  • Every method receives self automatically.
  • func __str() defines how the instance prints: print(obj) and the concatenation "…" + obj both use it.

Instantiation

class Animal
    func init(name, sound)
        self.name = name
        self.sound = sound
    end
    func speak()
        return self.name + " says " + self.sound
    end
end
var a = Animal("Dog", "woof")
print(a.speak())   ## Dog says woof
print(a.name)      ## Dog

Static methods

A method prefixed with static belongs to the class and not to an instance: it does not receive self. It is called as Class.method(...), or on an instance, with no self injected. Handy for alternative constructors, or for utilities tied to the class.

class Vec
    func init(x, y)
        self.x = x
        self.y = y
    end
    static func zero()      ## no self: a factory tied to the class
        return Vec(0, 0)
    end
end
var o = Vec.zero()          ## called on the class
assert(o.x == 0 and o.y == 0)

Inheritance

class Animal
    func init(name, sound)
        self.name = name
        self.sound = sound
    end
    func speak()
        return self.name + " says " + self.sound
    end
end
class Dog extends Animal
    func init(name)
        super.init(name, "woof")   ## calls the parent constructor
    end
    func fetch()
        return self.name + " fetches!"
    end
end

var d = Dog("Rex")
print(d.speak())   ## Rex says woof  (an inherited method)
print(d.fetch())   ## Rex fetches!

A child with no func init inherits the parent's.

super

super.method(args) calls the parent's method with the current self.

Equality and comparison

Bare maps and arrays compare by reference: a == b is true only when a and b name the same object in memory, never from their content. For a comparison by value, make it a class and define __eq.

## bare maps => compared by reference
print({x: 1} == {x: 1})            ## 0: the same content, but distinct objects
var m = {x: 1}
print(m == m)                      ## 1: the same reference

## an instance plus __eq => compared by value
class Point
    func init(x, y)
        self.x = x
        self.y = y
    end
    func __eq(other)
        return self.x == other.x and self.y == other.y
    end
end
print(Point(1, 2) == Point(1, 2))  ## 1: __eq compares the fields
print(Point(1, 2) == Point(3, 4))  ## 0
Two subtleties about __eq: it is looked up on the left operand only (when only the right one is an instance, the comparison stays by reference); and it is called even when both operands are the same instance — there is no identity short-circuit.

Graphics

The graphics module exposes raylib for real-time 2D rendering. It is available without any import. Rendering works on the desktop and in WASM.

The lifecycle

Three optional functions, called by the engine: setup() once at startup, then update(dt) and draw() on every frame.

## called ONCE after loading, before the loop
func setup()
    graphics.canvas(800, 600, "Title")
end

## called on every frame
func draw()
    graphics.clear(colors.BLACK)

    ## draw here

end

The three functions are independent: you may define just one. (You can also open the window at the script level rather than in setup.)

The mere presence of a draw() is enough to start a graphics session: if you do not call graphics.canvas(...), the engine creates a canvas of the default W×H size. Call graphics.canvas(w, h) only to choose another size or a title.

To keep the logic apart from the rendering, define update(dt) as well: the engine calls it before draw on every frame, with dt being the seconds elapsed since the previous frame. Multiplying the movements by dt makes the animation independent of the frame rate.

graphics.canvas(260, 140, "cycle")
var x = 0

## the logic: called BEFORE draw, dt = seconds since the previous frame
func update(dt)
    x = x + 120 * dt  ## 120 px per second, whatever the frame rate
    if x > 260 then x = 0 end
end

func draw()
    graphics.clear(colors.BLACK)
    graphics.fill(Color(1, 1, 1))
    graphics.circle(x, 70, 20)
end

You can also drive the loop explicitly with graphics.run(callback) if you would rather name your rendering function otherwise (update is still called first).

API

The module's rule: the geometry comes through the arguments, the style from the current state — fill, stroke, strokeSize, fontSize, font, rectMode, ellipseMode, spriteMode. No drawing primitive takes a colour or a size as an argument, and that state is reset to its defaults at the start of every frame.

Contexte persistant & modes de fusion

Le contexte de dessin n'est pas effacé automatiquement entre les frames : c'est à draw() de décider. Sans appel à graphics.clear(), le dessin s'accumule d'une frame à l'autre (traînées). Avec une couleur opaque, clear repart d'un fond net ; avec une couleur semi-transparente (alpha < 1), il applique un fondu — le contenu précédent s'estompe peu à peu vers cette couleur.

graphics.blendMode(mode) change la façon dont les dessins se combinent au contenu déjà présent. Le mode additif (blend.ADD), conjugué au contexte persistant et à un léger fondu, produit des lueurs et des traînées lumineuses.

graphics.canvas(240, 160)
global t = 0
func draw()
    graphics.blendMode(blend.ADD)         ## fusion additive (lueur)
    graphics.clear(Color(0, 0, 0, 0.08))  ## fondu léger → traînées
    t = t + 0.05
    graphics.fill(Color(0.2, 0.5, 1))
    graphics.circle(120 + math.cos(t) * 80, 80 + math.sin(t * 1.3) * 50, 14)
end

Le dessin 3D partage la même boucle et le même état que la 2D. On place une caméra, puis on dessine des formes entre graphics.begin3d(cam) et graphics.end3d(). Comme en 2D, fill/stroke pilotent le remplissage et le contour (fil de fer) — mais l'épaisseur du fil de fer 3D est fixe (1 px) : graphics.strokeSize ne s'applique qu'en 2D. Après end3d(), on peut dessiner un HUD 2D par-dessus dans la même frame.

La caméra est un objet (classe Camera, comme Color) : on la crée une fois puis on la pilote par ses méthodes. cam.setPos(x,y,z) fixe la position, cam.lookAt(x,y,z) réoriente vers une cible, cam.move(dx,dy,dz) translate la caméra et sa cible (visée conservée), cam.orbit(angle, radius [, height]) la place en orbite autour de sa cible (angle en radians).

En 3D, appelle graphics.clear(couleur opaque) au début de chaque frame : un effacement opaque remet à zéro le tampon de profondeur (indispensable au test de profondeur), en plus de la couleur.

Éclairage & texture

Les solides pleins (fill) sont dessinés par instancing avec un shader Blinn-Phong : toutes les formes d'un même type ne coûtent qu'un seul appel de dessin, et chacune garde sa propre couleur. L'éclairage est opt-in : tant qu'aucune lumière n'est déclarée, le rendu est plat (couleur unie). Dès qu'une lumière existe, les faces sont ombrées selon leur orientation.

Transformer les objets 3D

Les transformations (translate/rotate/scale) agissent aussi sur les solides 3D. translate(x,y,z) place, rotate(deg, ax,ay,az) (ou rotateX/Y/Z) oriente, scale(...) redimensionne. Elles sont cumulatives dans le bloc begin3d/end3d ; push()/pop() servent à isoler la transformation d'un objet (sauvegarde/restauration).

func draw()
    graphics.clear(colors.BLACK)
    graphics.begin3d(cam)
        ## chaque cube dans son propre bloc push/pop
        graphics.push()
            graphics.translate(-3, 0, 0)
            graphics.rotateY(elapsedTime * 60)   ## tourne autour de Y
            graphics.fill(colors.RED)
            graphics.cube(0, 0, 0,  2, 2, 2)
        graphics.pop()
        graphics.push()
            graphics.translate(3, 0, 0)
            graphics.rotate(elapsedTime * 90, 1, 1, 0)  ## axe quelconque
            graphics.fill(colors.SKYBLUE)
            graphics.cube(0, 0, 0,  2, 2, 2)
        graphics.pop()
    graphics.end3d()
end
## la caméra est un objet : créée une fois, pilotée par ses méthodes
global cam = graphics.camera(10, 6, 0,  0, 0, 0)
graphics.ambient(0.2)                         ## éclairage : base ambiante…
graphics.light("dir", -1, -2, -1)          ## …+ un « soleil » directionnel

func draw()
    graphics.clear(colors.BLACK)      ## efface color + profondeur
    cam.orbit(elapsedTime * 0.5, 10, 6)   ## orbite autour de la target (angle en radians)
    graphics.noStroke()
    graphics.begin3d(cam)
        graphics.grid(10, 1)
        graphics.fill(colors.RED)
        graphics.cube(-2, 1, 0,  2, 2, 2)   ## faces ombrées
        graphics.fill(colors.SKYBLUE)
        graphics.sphere(2, 1, 0,  1.2)
    graphics.end3d()
    graphics.fontSize(22)
    graphics.text("Ollin 3D", 12, 12)   ## HUD 2D par-dessus
end

Terrain voxel : géométrie retenue & culling

Pour un monde fait de milliers de cubes (type Minecraft), ré-émettre chaque cube à chaque frame est trop coûteux. Ollin propose une géométrie retenue : on cuit les cubes d'un « chunk » une seule fois dans des tampons GPU, puis on le redessine en un seul appel par frame. On ne dessine que les chunks visibles (test de frustum), et on libère les lointains → mémoire bornée, monde potentiellement infini.

NomDescription
graphics.beginChunk()Ouvre l'enregistrement : les graphics.cube/plane suivants sont cuits (enregistrés), pas dessinés
graphics.endChunk()Termine et renvoie un handle à redessiner chaque frame : map { id, idw, count, wcount }
graphics.drawChunk(handle)Redessine la partie opaque d'un chunk cuit en un seul appel (dans begin3d)
graphics.drawChunkAlpha(handle)Dessine la partie transparente (instances à fill alpha < 1, ex. eau). À appeler APRÈS tout l'opaque
graphics.freeChunk(handle)Libère les tampons GPU d'un chunk (lointain) → mémoire récupérée
graphics.inFrustum(x,y,z [, radius])La sphère (centre, rayon) est-elle (au moins en partie) visible par la caméra ? → 1/0. Sert au culling par chunk ; à appeler dans begin3d

Un chunk est automatiquement scindé en deux groupes selon l'alpha du fill : opaque (drawChunk) et transparent (drawChunkAlpha). Ordre obligatoire : dessine TOUT l'opaque, PUIS TOUTE la transparence — sinon le mélange alpha est incorrect.

Atlas de tuiles (texture par face)

Pour texturer un terrain sans un appel de dessin par matière, on utilise un atlas : une seule image en grille de tuiles. Chaque cube porte un triplet de tuiles (dessus / côté / dessous) ; le shader choisit selon la face (herbe dessus, terre sur les côtés…). L'atlas se génère en Ollin avec le module image (pixels) ou se charge depuis une image.

NomDescription
graphics.tileset(img, cols, rows)Déclare l'atlas de tuiles (grille cols×rows, filtrage NEAREST = pixels nets)
graphics.tile(t)Même tuile t sur les 6 faces du prochain cube (état, comme fill) ; -1 = aucune (couleur pleine)
graphics.tiles(dessus, côté, dessous)Tuiles distinctes par face (indices dans l'atlas)
graphics.tileAnim(t)Désigne une tuile dont l'UV défile dans le temps (eau qui ondule)
graphics.corners(a, b, c, d)Hauteurs des 4 coins du dessus du prochain cube (état), en fraction de sa hauteur : (-x,-z), (+x,-z), (-x,+z), (+x,+z). Sans argument = dessus plat

Un cube à coins déformés reste un cube instancié : le déplacement se fait dans le vertex shader, donc sans coût de draw call. Deux cubes voisins qui donnent la même valeur au coin qu'ils partagent forment une surface continue — de quoi faire épouser à un terrain sa hauteur non arrondie au lieu d'une marche. À réserver aux rendus qui le cherchent : l'exemple Univers voxel, lui, garde des cubes tous identiques.

Avec un atlas actif, donne une tuile à chaque cube du chunk (tile/tiles) : un cube sans tuile échantillonnerait la tuile 0 au lieu d'une couleur pleine.
## chunk voxel : cuisson UNIQUE dans setup(), redessin en 1 appel par frame
global cam = graphics.camera(26, 20, 26,  8, 3, 8)
global chunk = nil

func setup()
    graphics.canvas(W, H, "voxel")
    graphics.ambient(0.5)
    graphics.light("dir", -0.5, -1, -0.35)
    graphics.beginChunk()                 ## début de la cuisson
    graphics.fill(colors.WHITE)
    for x = 0, 15 do
        for z = 0, 15 do
            var h = math.floor(math.noise(x * 0.12, z * 0.12) * 6) + 1
            for y = 0, h do
                graphics.cube(x, y, z,  1, 1, 1)
            end
        end
    end
    chunk = graphics.endChunk()           ## handle persistant
end

func draw()
    graphics.clear(Color(0.55, 0.8, 0.95))
    cam.orbit(elapsedTime * 0.3, 26, 20)
    graphics.begin3d(cam)
        if graphics.inFrustum(8, 3, 8, 20) then   ## dessiné seulement si visible
            graphics.drawChunk(chunk)                 ## 1 appel = tout le chunk
        end
    graphics.end3d()
end

Module touch

Suit plusieurs doigts à la fois, chacun par un identifiant stable. C'est ce qu'il faut pour deux notes tenues ensemble, une manette à deux pouces ou un pincement — là où mouse ne rapporte qu'un seul point.

RappelAppelé quand
touch.began(id, x, y)un doigt se pose
touch.moved(id, x, y)un doigt se déplace
touch.ended(id, x, y)un doigt se lève, à sa dernière position connue

L'état se lit aussi directement, sans rappel : touch.count() donne le nombre de contacts, touch.points() un tableau de {id, x, y}. Les coordonnées sont dans le même repère que celles de mouse.

## Une note par doigt : l'identifiant sert de clé, donc plusieurs sonnent ensemble.
global under = {}

func touch.began(id, x, y)
    under[id] = keyAt(x, y)
    sound.tone(sound.note(notes[under[id]]), 0.5).play()
end

func touch.ended(id, x, y)
    under[id] = nil
end
Les rappels de mouse ne sont pas supprimés : sur un doigt unique, le système émule la souris, si bien qu'un script déclarant les deux familles reçoit le geste deux fois. Écrivez donc chaque chemin pour qu'un doublon soit sans effet, ou n'écoutez qu'une famille.

Ce qu'il faut savoir

  • Jusqu'à huit contacts sont suivis. Un neuvième doigt est ignoré, comme le fait le moteur graphique lui-même.
  • Sur un ordinateur, une souris n'a qu'un pointeur : touch.count() y vaut toujours zéro, et c'est mouse qui rend service.
  • Le suivi est reconstruit par le moteur : la couche graphique ne donne qu'une photographie des contacts à chaque image, sans dire lequel vient d'apparaître. C'est la comparaison d'une image à la suivante qui produit les trois rappels.
  • L'identifiant reste le même du début à la fin d'un geste, mais il est réutilisé ensuite : ne le conservez pas au-delà de ended.
  • Une page web doit poser touch-action: none sur son canvas, sans quoi deux doigts déclenchent le zoom du navigateur au lieu d'atteindre le programme. Les vues du site le font déjà.

Module ui

Boutons, cases à cocher et sliders dessinés par le moteur, en pile dans le coin haut droit de la zone de tracé. Aucune dépendance au navigateur : le même code tourne en natif, sous un affichage virtuel et dans le playground.

Un widget se déclare une fois — au niveau du fichier ou dans setup(). Le moteur le dessine et le teste à chaque frame : il n'y a rien à appeler dans draw().

L'interface est fermée au démarrage : elle se réduit à une poignée à trois barres dans le coin, pour ne pas masquer la scène. Un clic dessus déplie le menu affiché, dont la ligne de tête reprend la poignée et le titre du menu ; un clic sur cette tête referme.

global grid = true
global speed = nil   ## le slider l'initialise à son default

func resetAll()
    t = 0
end

ui.button("Remettre à zéro", resetAll)
ui.checkbox("Grid", ref grid)
ui.slider("Vitesse", ref speed, 0.25, 3, 1.0)

func draw()
    if grid then       ## lecture NORMALE de la variable liée
        drawGrid()
    end
end

API

FonctionDescription
ui.button(label, fn)Ajoute un bouton. La fonction est appelée à chaque clic, sans argument.
ui.checkbox(label, ref variable [, onChange])Ajoute une case à cocher liée à une variable, passée par référence. L'état initial est lu dans la variable ; chaque clic y écrit true ou false, puis appelle onChange(nouvelEtat) si la fonction est fournie.

Listes

Une liste choisit un élément parmi plusieurs. Sa source est un tableau, une map ou un enum, et la règle d'affichage est celle de for … in : un tableau donne ses valeurs, une map ou un enum ses clés. La variable liée reçoit exactement ce qui est affiché — la valeur pour un tableau, la clé pour une map ou un enum.

global shapes = ["cercle", "carré", "triangle"]
enum Dir
    clockwise,
    counterClockwise
end
global shape = nil      ## la liste l'initialise au 1er élément
global dir = nil

func setup()
    var menu = ui.menu("Réglages")
    menu.list("Forme", shapes, ref shape)        ## shape reçoit "cercle", "carré"…
    menu.list("Sens", Dir, ref dir, onDir)   ## dir reçoit "clockwise" ou "counterClockwise"
    ui.show(menu)
end
  • La ligne affiche le libellé et l'élément retenu ; un clic déplie la liste, où l'élément courant porte une marque ronde. Choisir referme la liste et revient au menu. element.open() la déplie depuis le programme, comme pour un sous-menu.
  • La sélection est toujours définie : une variable à nil est initialisée au premier élément. Une valeur déjà posée est conservée.
  • Les éléments sont relus à chaque ouverture : modifier la source entre deux ouvertures se voit, sans rien coûter par frame.
  • L'ordre est figé, car une map n'en a pas : un enum est trié par valeur — donc dans l'ordre de déclaration —, une map ordinaire par libellé. Un tableau garde l'ordre de ses index.
  • surChange reçoit l'élément choisi.

Menus

Les widgets peuvent être rangés dans des menus. Un seul menu est affiché à la fois : un sous-menu apparaît comme une ligne cliquable marquée d'un chevron, cliquer dessus descend d'un niveau, et une ligne < remonte. Un menu se déclare comme un widget, et porte les mêmes méthodes de déclaration.

var settings = ui.menu("Réglages")
settings.checkbox("Grille", ref grid)

var display = settings.menu("Affichage")   ## sous-menu de settings
display.checkbox("Trait épais", ref thick)

var game = ui.menu("Jeu")
game.button("Rejouer", replay)

ui.show(settings)   ## menu global affiché
ui.show(game)        ## bascule vers un autre menu global

Un clic sur un widget n'est pas transmis à mouse.pressed : cliquer un bouton de l'interface ne déclenche donc pas aussi l'action de la scène. Un clic ailleurs parvient normalement au script.

Ce qu'il faut savoir

  • La taille de l'interface est proportionnelle à la hauteur de la zone de tracé, donc lisible aussi bien sur un écran de bureau que sur un téléphone, dont la toile compte plusieurs pixels par pixel d'affichage.
  • L'indicateur de mémoire et d'images par seconde occupe le coin bas droit, à l'opposé de la pile.
  • Les libellés utilisent la police par défaut du moteur (voir graphics.font), et non celle que le script a choisie : l'interface garde son apparence quoi que fasse le programme.
  • Retirer un menu où l'on se trouve fait remonter l'affichage au premier menu parent encore présent. Utiliser un handle retiré lève une erreur explicite.
  • Un slider donne une valeur entière si ses bornes et sa valeur de départ le sont, sinon flottante : ui.slider("Facteur", ref f, 0, 1, 0.5) règle donc un flottant malgré ses bornes entières.
  • La variable liée est la seule source de vérité : la glissière lit sa valeur à chaque frame, donc le programme peut l'écrire lui-même et l'affichage suit. Une valeur hors plage est ramenée aux bornes à l'affichage, sans écrire dans la variable.
  • ref accepte un chemin de champs : ui.checkbox("Grille", ref config.grille) permet de regrouper tous les réglages dans un seul objet plutôt que d'éparpiller des variables globales (voir l'exemple « Interface (ui) »).
  • La variable d'une case doit être accessible : un global ou un champ d'objet. Une variable locale à une fonction n'a pas de sens ici, puisqu'elle disparaît avant le premier clic.
  • Sans zone graphique — exécution en ligne de commande sans fenêtre —, déclarer un widget ne fait rien, mais les arguments sont tout de même vérifiés.

tween.cancelAll()Annule tout (changement d'écran, fin de partie)

Le handle renvoyé porte pause(), resume(), cancel(), isDone(), progress(), delay(seconds) et repeat(…). Les méthodes renvoient le tween, donc elles se chaînent.

Répéter : repeat

Une animation se lit par parcours. repeat([occurrences] [, allerRetour]) en règle le nombre : sans compte, la répétition est sans fin ; le second paramètre ajoute au programme sa lecture en arrière.

ÉcritureCe qui est joué
tween.to(…)un aller
.repeat(2)aller, aller
.repeat(2, true)aller, aller, retour, retour
.repeat()aller, aller, … sans fin
.repeat(nil, true)aller-retour sans fin

Le compte est reconnu par sa position, d'où le nil : true vaut 1 en Ollin, donc repeat(true) ne se distinguerait pas de repeat(1).

L'aller-retour porte sur l'ensemble des occurrences, non sur chacune : repeat(2, true) joue les deux allers puis les deux retours. Pour alterner à chaque fois, composez deux appels — repeat(nil, true).repeat(2) donne deux allers-retours. C'est la différence avec GSAP ou Phaser, où yoyo inverse chaque répétition.

Chaque parcours rejoue l'animation entière dans son sens : entre deux allers la valeur revient donc au départ, et entre deux retours elle repart de la cible. Les bornes sont figées au premier démarrage — écrire dans l'objet en pleine animation ne redéfinit pas le départ du parcours suivant. progress() couvre tout le programme (un plan de quatre parcours rend 0,5 à la moitié du deuxième) ; sans fin, il rend l'avancement du tour en cours.

Attention : une répétition sans fin ne se termine jamais d'elle-même et retient l'objet animé tant que cancel() — ou tween.cancelAll() — n'a pas été appelé.

## Une pulsation : le radius grossit puis revient, sans fin.
tween.to(ball, {r: 40}, 0.6, "easeInOutQuad").repeat(nil, true)

## Trois clignotements, puis on s'arrête sur la color de départ.
tween.to(ball, {tint: Color(1, 0.3, 0.2)}, 0.2).repeat(nil, true).repeat(3)

Enchaîner : tween.sequence

tween.sequence(object, [steps]) joue une suite d'animations l'une après l'autre. Chaque étape est une map, et la clé de temps s'appelle delay dans les deux rôles : la durée de l'animation quand l'étape porte to, une simple attente quand elle ne le porte pas.

CléRôle
toles champs visés, comme dans tween.to : {y: 300}
delaydurée de l'étape en secondes — ou attente si l'étape n'a pas de to
curvenom de courbe ou fonction, propre à cette étape
targetun autre objet à animer ; sans elle, l'objet passé en premier argument

Toute autre clé est refusée, avec la liste des clés admises : un duration ou un easing mal choisi échoue franchement au lieu d'être ignoré en silence.

La valeur de départ d'une étape est celle que la précédente a laissée, lue à son démarrage — deux étapes qui se suivent s'enchaînent donc sans saut. repeat porte sur la suite entière et son aller-retour la rejoue à l'envers, chaque étape inversée. progress() court sur toute la suite, en temps : des étapes de durées inégales donnent une progression régulière.

tween.sequence(ball, [
    {to: {y: 300}, delay: 0.4, curve: "easeOutQuad"},
    {to: {y: 100}, delay: 0.6, curve: "easeInQuad"},
    {delay: 0.2},                                ## une pause
    {target: shadow, to: {a: 0}, delay: 0.5},   ## un autre objet
])

L'exemple « Séquence animée (tween) » fait rebondir une balle en cinq étapes : la chute, l'écrasement à l'impact, la détente, la remontée et une pause. Ce sont les durées inégales — un dixième de seconde pour l'écrasement contre une demie pour la chute — qui donnent son poids à la balle.

Le handle renvoyé est celui d'un tween ordinaire : pause(), cancel(), isDone(), delay() et repeat() s'y appliquent tels quels. Écraser l'un des champs animés par un autre tween annule la séquence, comme pour tween.to.

## Le dessin lit des champs ; le temps ne l'intéresse pas.
global ball = {x: 0, r: 20, tint: Color(0.3, 0.7, 1)}

func setup()
    graphics.canvas(W, H)
    ## Plusieurs champs d'un coup, dont une COULEUR (interpolée composante par composante).
    tween.to(ball, {x: W * 0.8, r: 60, tint: Color(1, 0.45, 0.2)}, 1.2, "easeOutBack")
    ## Puis un retour, 0,3 s après la fin du premier.
    tween.to(ball, {r: 20}, 0.8, "easeInQuad").delay(1.5)
end

func draw()
    graphics.clear(colors.BLACK)
    graphics.fill(ball.tint)
    graphics.circle(ball.x, CH, ball.r)
end

Courbes

linear, puis les familles easeIn / easeOut / easeInOut déclinées en Quad, Cubic, Sine, Expo et Back, plus easeOutElastic et easeOutBounce. Défaut : easeInOutQuad. Une fonction peut aussi tenir ce rôle — elle reçoit la progression sur [0;1] et rend la progression corrigée :

tween.to(obj, {x: 100}, 1, func(p) return p * p * p end)
Les deux derniers arguments sont reconnus par leur type : une chaîne ou une fonction donne la courbe, la fonction suivante est le rappel de fin. Aucun ordre à retenir.

tween.curves() se prête directement à une liste du module ui : la source est le catalogue du moteur, et la variable liée reçoit le nom choisi. C'est ce que fait l'exemple « Animations (tween) ».

menu.list("Courbe", tween.curves(), ref config.curve, onCurve)

Ce qu'il faut savoir

  • La valeur de départ est lue au démarrage de l'animation, pas à la déclaration : avec un delay, le tween part de la valeur qu'aura le champ à l'échéance.
  • Déclarer un tween sur un champ déjà animé annule le précédent : deux animations ne se battent jamais pour la même valeur. Deux ref distincts sur la même variable ne sont pas reconnus comme telle, en revanche — le langage ne permet pas de les comparer.
  • Si la valeur de départ et la cible sont entières, la valeur reste entière tout du long.
  • Une valeur cible peut être une instance de classe : les champs numériques communs sont interpolés un à un, ce qui couvre Color comme un Vec2 écrit par vos soins. Le tween écrit dans l'instance, il ne la remplace pas.
  • La valeur finale posée est la cible exacte : une courbe à dépassement ne rend pas tout à fait 1 en fin de course, et un arrondi laisserait 0,999.
  • Le rappel de fin peut déclarer d'autres tweens — de quoi enchaîner des étapes — ou tout annuler.

Modules audio et sound

Le son se partage en deux : audio est la session — le périphérique, le volume général, la pause — et sound est ce qui sonne. Aucun fichier n'est nécessaire : tous les sons de cette page sont calculés.

sound offre deux natures d'objet, et la différence n'est pas cosmétique :

  • un oscillateur vivant, dont on déplace la fréquence pendant qu'il sonne — une sirène, un vibrato piloté à la souris ;
  • un tampon figé, calculé une fois puis déclenché — un bip, une note, une boucle rythmique.

Un oscillateur

global siren = sound.saw(220)

func setup()
    graphics.canvas(W, H)
    siren.volume(0.3).start()
end

func draw()
    ## La fréquence suit la souris : c'est tout l'intérêt d'un oscillateur vivant.
    siren.freq(200 + 600 * mouse.x / W)
end
FabriqueRôle
sound.osc(freq [, forme])oscillateur, forme donnée par son nom
sound.sine / square / saw / triangleraccourcis : la forme est dans le nom, donc jamais mal orthographiée
sound.noise()bruit blanc (la fréquence ne s'y applique pas)

Méthodes d'un oscillateur : start, stop, isPlaying, freq, volume, pan, shape, envelope, trigger, release, free. Comme ailleurs dans le moteur, sans argument elles lisent, avec un argument elles écrivent et rendent l'objet : o.freq(440).volume(0.2).pan(-1).

Une enveloppe, pour jouer des notes

Un oscillateur qu'on démarre et qu'on arrête produit un son plat. L'enveloppe ADSR lui donne une attaque, un déclin, un maintien et un relâchement — c'est ce qui distingue une note d'un signal de test.

global voice = sound.triangle(440).envelope(0.01, 0.08, 0.5, 0.25)

func mouse.pressed(x, y)
    ## Avec une duration, le relâchement part tout seul à l'échéance.
    voice.freq(sound.note("C4")).trigger(0.2)
end

trigger() sans durée tient la note jusqu'à release(). Une note relâchée libère sa voix, si bien qu'un programme peut en déclencher indéfiniment. Quand tu n'as plus besoin d'un oscillateur, free() le rend au moteur : la note finit de s'éteindre, puis la voix redevient disponible — c'est ce qui permet d'en créer un par doigt posé plutôt que de les pré-allouer. Le handle est alors périmé, et le réutiliser lève une erreur explicite. Les hauteurs s'écrivent en clair : sound.note("C#4") rend 277,18 Hz, et un nom de note est accepté partout où une fréquence l'est.

Un tampon calculé

sound.tone(freq, duration [, forme]) échantillonne une forme d'onde ; sound.generate(duration, formule) échantillonne votre formule, qui reçoit le temps en secondes et rend une amplitude dans [-1;1].

global beep = sound.tone(880, 0.12, "square").envelope(0.005, 0.02, 0.6, 0.05)

## Une cloche : un sinus qui s'éteint tout seul.
global bell = sound.generate(1.2, func(t)
    return math.sin(t * 6.283 * 660) * math.exp(-t * 3)
end)

beep.play()
bell.volume(0.4).play()

La formule est évaluée une seule fois, à la construction — jamais pendant la lecture. Méthodes d'un tampon : play, stop, isPlaying, volume, pan, rate, loop, envelope, plus trois accesseurs qui lisent le son calculé.

AccesseurRend
duration()la durée du tampon, en secondes
peak()l'amplitude maximale, en valeur absolue
sample(t)l'échantillon à l'instant t ; zéro hors du tampon

rate change la vitesse de lecture, donc la hauteur et la durée, comme un disque qu'on accélère : ce n'est pas une transposition.

La session

AppelRôle
audio.volume([v])volume général, borné à [0;1]
audio.pause() / resume()suspend l'avancement du son, et non son seul volume
audio.isPaused() / isReady()état de la pause, et du périphérique
audio.start()ouvre le périphérique ; rarement utile (voir ci-dessous)

Un navigateur refuse de sonner avant une interaction. Le moteur ouvre donc le périphérique au premier clic ou à la première touche, et il n'y a rien à écrire pour cela. En revanche, un son demandé dans setup() ne s'entendra qu'après ce premier geste.

Ce qu'il faut savoir

  • Le calcul des ondes ne dépend pas du graphisme : un tampon se construit et se mesure même sans carte son, ce dont la suite de tests du moteur se sert.
  • Seize oscillateurs et trente-deux sons coexistent. Quand la table est pleine, le plus ancien arrêté est recyclé — un son qui joue n'est jamais volé —, et son ancien objet devient invalide.
  • Aucun code Ollin ne tourne dans le circuit audio : la formule d'un generate est échantillonnée d'avance, et la forme d'un oscillateur est calculée par le moteur. C'est ce qui évite les craquements.
  • En natif, le son continue même si un calcul occupe la machine virtuelle ; dans le navigateur, le mélange partage le fil de la page, donc une frame très lourde peut s'entendre.
  • Hors périmètre pour l'instant : le chargement de fichiers, les effets, l'enregistrement et la spatialisation.

Module image

Le module image permet de charger des textures depuis le disque (ou des données base64) et de créer des render textures pour le rendu hors-écran. Disponible sans import.

graphics.canvas() doit être appelé avant toute opération image — le contexte GL doit exister.

Charger une image

graphics.canvas(240, 140, "image.load")
var tex = image.load("assets/smiley.png")  ## handle {id, width, height} — ressource servie

func draw()
    graphics.clear(Color(0.1, 0.12, 0.2))
    graphics.sprite(tex, 20, 40, 64, 64)   ## 64×64
    graphics.sprite(tex, 120, 25, 96, 96)  ## redimensionné
end
image.load(name) résout le nom ainsi : en natif, un fichier du disque ; en WASM, d'abord une image chargée via le bouton « Images », sinon une ressource servie par le site (même origine, récupérée automatiquement — ex. image.load("assets/logo.png") relatif à la page). Pour une image embarquée dans le script (portable partout, sans réseau), utiliser image.loadData("png", base64) — voir l'exemple « Image (loadData) » du playground.

Render texture (dessin hors-écran)

graphics.canvas(180, 180, "render texture")
var rt = image.create(120, 120)  ## render texture 120×120

image.beginDraw(rt)             ## on dessine DANS la texture (une fois)
    graphics.clear(Color(0.1, 0.1, 0.15))
    graphics.fill(colors.RED)
    graphics.circle(60, 60, 50)
image.endDraw()

func draw()                      ## puis on l'affiche comme un sprite
    graphics.clear(colors.BLACK)
    graphics.sprite(rt, 30, 30)
end
