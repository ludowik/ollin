Engine performance

Two quantities, two statuses. The work — the number of instructions executed — is deterministic: it compares from one version of the engine to the next, and it is what we mean when we say a change costs or saves. The time, on the other hand, depends on the machine, on the compiler and even on the address the code is placed at: it only counts as a reading, on a given date and a given piece of hardware.

Method

Why two instruments. Every opcode handler of the virtual machine lives in a single function (computed-goto dispatch), so changing any one of them moves the address of all the others and alters how the instruction cache behaves. The effect is measured at ±7%: adding dead code to a handler the test never executes is enough to make it 7% faster. A difference of a few per cent in a time therefore says nothing about a real cost. The instruction count, by contrast, is indifferent to the code's address and to the cache. Instructions up: a real cost, to be fixed. Instructions steady while the time moves: placement, and nothing to optimise — freezing a favourable layout would serve no purpose, the next change undoing it.

The work. Read by bash bench/icount.sh <ref> [<ref>], which builds each version in a throwaway workspace and counts the instructions executed (callgrind). One milestone per day measures the state at the end of that day: the change shown adds up every commit of the day, and the subject named — the last one's — deserves neither the credit nor the blame. Attributing a change to one commit means measuring that commit. Only the days touching the engine's core are marked; elsewhere the count is steady by construction. The lower bound is not the git history but the language: before 20 June 2026, these three scripts do not run.

The time. Read by bash bench/bench_all.sh. Every test is run several times and the best time is kept, a single run being too sensitive to contention for the processor. All three languages measure processor time, not elapsed time. No environment is normative: neither the times nor the multiples carry over from one machine or one session to another, and two figures compare only when measured in the same series.
