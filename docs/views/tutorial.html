Introduction

Ollin is a minimal, expressive scripting language: dynamically typed, compiled, and designed to be embedded.

A first program

print("hello world!")

Truth rules (true/false)

One principle: the empty is false. A value is false when it stands for absence or emptiness (nil, false, zero, an empty string, map or array); everything else is true.

ValueFalse when
nilalways
boolfalse
integer== 0
float== 0.0
stringthe empty string ""

assert(1 <> true)   ## distinct types: the boolean is sealed
assert(not 0)        ## zero => false, without being equal to false
assert("not empty")  ## a non-empty string => true
assert(not "")      ## an empty string => false

The two rules are independent, and both hold at once: zero is false (the empty is false), and yet zero is not false (the types do not mix). In other words, if x and if not x tell the truth of a value whatever its type — that is how a test is written — whereas x == false only holds for a genuine boolean. There is no bool(v) conversion: not not v does the job.

Arithmetic on the numeric types

Two integers combined give an integer — except for division /, which always gives a float. As soon as a float takes part in the computation, the result is a float.
assert(7 / 2 == 3.5)  ## division => always a float
assert(7 % 2 == 1)    ## modulo => int when both are ints

Variables

Every variable must be declared before use — using or assigning an undeclared name is a compile error.

var creates a variable local to the current function; global creates a global variable visible throughout the program.

Naming

A name starts with a letter or an underscore, followed by letters, digits or underscores (_counter, x1, final_score). It is case sensitive (score ≠ Score), and accented letters are not supported. The language's keywords (var, if, end…) cannot serve as names.

var a = 10
var b = 2.5
var s = "hello"
var undef  ## no initialisation => nil
assert(undef == nil)

Multiple declaration

var x, y = 1, 2
var p, q, r = 10, 20  ## r => nil (not enough values)

Assignment

var a = 10
a = 42  ## plain
a += 1  ## compound: += -= *= /= %=
a *= 2
assert(a == 86)
Underscores in numeric literals are ignored: 1_000_000 == 1000000.

Global variables — global

The global keyword declares a global variable, visible throughout the program. It can be declared anywhere, and read or changed from any function. A local variable (var) of the same name hides the global from its declaration onwards: before that line the name still means the global, so var x = x initialises from the outer value.

global counter = 0

func incr()
    counter += 1  ## changes the global from a function
end

incr()
incr()
assert(counter == 2)
print(counter)    ## 2
var always creates a local variable; global creates a global one, visible everywhere. Assigning an undeclared name remains a compile error.

Constants — const

The const keyword declares an immutable local. Initialisation is mandatory. Any later attempt to assign to it is a compile error.

const PI = 3.14159
const MAX = 100

assert(PI == 3.14159)
assert(MAX == 100)

func area(r)
    const TWO_PI = 2 * PI
    return TWO_PI * r * r
end

print(area(1))  ## 6.28318…
The following errors are caught at compile time: 
const x  ## ERROR: must be initialized
const x = 1
x = 2    ## ERROR: cannot assign to const 'x'

The bitwise operators work on integers only. ~ is XOR as a binary operator and NOT as a unary one; ^ is reserved for the power.

~ is XOR between two operands (a ~ b) and NOT as a prefix (~a). ^ is not a bitwise operator: it is the power (see Operators).

Precedence

From the lowest to the highest:

or  =>  and  =>  |  =>  ~(xor)  =>  &  =>  comparisons  =>  << >>  =>  + -  =>  * / %  =>  ~(not) - not  =>  ^

Examples

var flags = 0
flags = flags | 1         ## turn bit 0 on
flags = flags | 4         ## turn bit 2 on
assert(flags == 5)        ## 0101

assert((flags & 1) == 1)  ## test bit 0
assert((flags & 2) == 0)  ## bit 1 is not set

flags = flags ~ 1         ## XOR: flip bit 0 => 4
assert(flags == 4)

assert(1 << 8 == 256)
assert(256 >> 4 == 16)
assert(~0 == -1)
assert(255 & 15 == 15)
The bitwise operators need integer operands. Applying &, |, ~, << or >> to a float raises an error at run time.

Strings

var s = "hello"
assert(s == "hello")
assert(not "")   ## an empty string is false
assert("text")  ## a non-empty one is true

Concatenation uses +:

var greeting = "Hello, " + "world" + "!"
assert(greeting == "Hello, world!")
Strings are immutable. Only + is overloaded for strings — the other operators (-, *…) stay reserved for numbers.

Interpolation

Any expression in braces {…} is evaluated and inserted. \{ inserts a literal brace.

var name = "Ada"
var n = 42
assert("Hello {name}, n={n}" == "Hello Ada, n=42")
assert("result: {n * 2 + 1}" == "result: 85")

An optional format follows a : — a C conversion specification, without the %: .3f (precision), 04x (width plus zeros), -8s (left aligned)…

assert("pi = {3.14159:.2f}" == "pi = 3.14")
assert("hex = {(255):04x}" == "hex = 00ff")
assert("pad = [{n:5d}]" == "pad = [   42]")
An empty {}, or an integer ({1}, {2:.2f} — indexed from 1), is a positional placeholder left as it is: it is filled by printf's arguments (see Builtins), not by interpolation. Both sides share the same formatting engine.

Multi-line expressions

Line breaks are treated as whitespace — an expression may span as many lines as needed, with no special syntax.

var total =
    net_price
    * ((1 + vat) / 100)
    + shipping

if order_valid
    and in_stock
    and payment_ok then
    ship()
end
then, do and end delimit the blocks — brackets around a condition are never required.
The other side of that freedom: a line that could continue the previous one does, since a statement ends when the expression can no longer be extended and not at the end of its line. There is nothing to watch out for, though — a line beginning with an operator, a ., a ( or a [ is linked to the expression above, which is exactly what one reads. No statement begins with any of those, and one that tried is refused: write f(7), not (f)(7) on a line of its own.

If / Else

if condition then
    ## the then block
elseif other_condition then
    ## elseif (as many as needed)
else
    ## an optional else
end
var score = 75
var grade = "F"

if score >= 90 then
    grade = "A"
elseif score >= 80 then
    grade = "B"
elseif score >= 70 then
    grade = "C"
else
    grade = "F"
end

assert(grade == "C")
print(grade)  ## C
To chain conditions, use elseif. There is no "else if" sugar: an else followed by an if is an else branch containing a nested if block, with an end of its own.

While

var i = 0
while i < 10 do
    i += 1
end
assert(i == 10)

## break leaves the loop at once
var k = 0
while true do
    k += 1
    if k >= 5 then break end
end
assert(k == 5)

For

Two forms for numeric loops: by interval (for i in [a;b]) or by explicit bounds (for i=a,b). For iterating over maps and arrays, see Iterating over a map and Arrays.

Range [a;b]

Mathematical interval notation — inclusive or exclusive bounds, with an optional step.

var sum = 0
for i in [1;10] do
    sum += i
end
assert(sum == 55)  ## 1+2+…+10 (inclusive on both sides)

## right-exclusive: 1,2,...,9
for i in [1;10[ do
    print(i)
end

## with a step: 1,3,5,7,9
for i in [1;10;2] do
    print(i)
end

## first class: it can be held in a variable
var r = [1;5]
for i in r do
    print(i)       ## 1 2 3 4 5
end

Numeric i=start,end[,step]

The step is optional — positive or negative.

## the implicit step is 1
for i=1,5 do
    print(i)  ## 1 2 3 4 5
end

## a positive step (even numbers)
for i=0,10,2 do
    print(i)  ## 0 2 4 6 8 10
end

## a negative step (counting down)
for i=5,1,-1 do
    print(i)  ## 5 4 3 2 1
end

Break inside a for

for i in [1;100] do
    if i > 3 then break end
    print(i)  ## 1 2 3
end

Switch

switch compares an expression against several values. Each branch starts with case followed by one or more comma-separated values. The else block runs when no case matches.

A branch does not fall through to the next one: there is nothing to break out of, and break is refused inside a switch. Written inside a loop it would read as leaving that loop, whereas it could only ever leave the switch — so it is a compile error rather than a silent misunderstanding. To leave the loop from a branch, use a flag or return. continue, on the other hand, goes through and reaches the loop, and a loop written inside a branch keeps its own break.

The case values are expressions, not constants: case n + 2 and case f() are valid. They are evaluated in order and only until one matches, so a case placed after the branch taken never runs. Matching uses ==: 1 and 1.0 are the same value, "1" and 1 are not.

var x = 2
switch x
case 1
    print("one")
case 2, 3
    print("two or three")
else
    print("other")
end

Switch on strings

var cmd = "start"
switch cmd
case "start", "go"
    print("starting")
case "stop"
    print("stopping")
else
    print("unknown command")
end

The do … end block

A do … end block creates a local lexical scope: variables declared inside are not visible after end. It is handy for isolating temporaries without writing a function.

var x = 0
do
    var tmp = 42
    x = tmp + 1
end
## tmp no longer exists here
assert(x == 43)

Closures created inside capture the block's variables as usual:

var fns = []
do
    var i = 99
    fns.push(func() return i end)
end
assert(fns[1]() == 99)
do blocks nest freely. A variable of an outer scope stays reachable inside an inner block.

Functions

func add(a, b)
    return a + b
end

assert(add(3, 4) == 7)

A function on a map field

func obj.field(...) defines a function straight onto a field of a map or a module — sugar for obj.field = func(...) ... end. Handy for the engine hooks (keyboard.keypressed, for instance).

var obj = {}
func obj.greet(name)
    return "greet " + name
end
assert(obj.greet("ollin") == "greet ollin")
A return ends its block: nothing may be written after it, and a statement that tries is refused. Code placed after a return would never run, and its author meant it to.

Multiple returns

func minmax(a, b)
    if a < b then
        return a, b
    end
    return b, a
end

var lo, hi = minmax(7, 3)
assert(lo == 3 and hi == 7)

Recursion

func fact(n)
    if n < 2 then return 1 end
    return n * fact(n - 1)
end

assert(fact(10) == 3628800)

Optional call — f?()

The syntax f?(args) is exactly sugar for if f then f(args) else nil:

  • f false (nil, 0, "", [], {}) → no call, the result is nil, and the arguments are not evaluated, so there is no side effect;
  • f callable → an ordinary call;
  • f true but not callable (an integer, a string…) → a run-time error, as for an ordinary call.

The typical use is an optional callback (nil → skipped, with nothing run). It applies to every form of call, methods included (obj.m?() injects self; a missing method gives nil) and super.m?(). In the implementation it is a plain JUMP_IF_FALSE followed by the standard call — there is no dedicated opcode.

func greet() return "hello" end
assert(greet?() == "hello")  ## callable => an ordinary call

var cb = nil
assert(cb?() == nil)         ## nil => no call, and no error

## an optional callback plus an optional method call (self injected)
class Box
    func init(v) self.v = v end
    func get() return self.v end
end
var b = Box(7)
assert(b.get?() == 7)        ## self injected
assert(b.missing?() == nil)  ## a missing method => nil
A true value that is not callable is still an error: (42)?() raises "call on non-function value" (42 being true, the call is attempted). Only false values are skipped. The ? acts on the call immediately to its left, and on nothing else.

Variadic arguments

... captures every extra argument.

func log(level, ...)
    printf("[{}] ", level)
    print(...)
end

log("INFO", "starting", "ok")  ## [INFO] starting ok

Passing the varargs on to another function

func wrapper(a, ...)
    return a, ...  ## passes the varargs on
end

var x, y, z = wrapper(1, 2, 3)
assert(x == 1 and y == 2 and z == 3)

In the last position of a list, ... expands to all the varargs: as a call argument (f(a, ...)), an array element ([x, ...]), a return (return a, ...) or a multiple assignment (var a, b = ...). A call in last position likewise expands to all its values (f(g()), return g(), [x, g()]). Anywhere else the expression is trimmed to a single value (... → the first argument, or nil).

Default parameters

A default value must be a literal constant.

func greet(name, greeting="Hello")
    printf("{}, {}!", greeting, name)
end

greet("Alice")         ## Hello, Alice!
greet("Bob", "Hi")     ## Hi, Bob!
func connect(host="localhost", port=8080, debug=false)
    printf("{}:{} debug={}", host, port, debug)
end

connect()                    ## localhost:8080 debug=0
connect("prod.example.com")  ## prod.example.com:8080 debug=0
connect("prod", 443)         ## prod:443 debug=0

Closures

A function can capture the variables of the scope around it. The captured value stays alive even after the outer function has returned.

An encapsulated counter

func make_counter()
    var n = 0
    func inc()
        n += 1
        return n
    end
    return inc
end

var c1 = make_counter()
var c2 = make_counter()  ## independent state

assert(c1() == 1)
assert(c1() == 2)
assert(c2() == 1)        ## c2 starts again from 0

Closures created in a loop

Every iteration has variables of its own: a function created in the body captures the loop variable and the body's locals as they were on its pass, not their final value.

var fns = []
for i = 1, 3 do
    var square = i * i
    fns.push(func() return i + square end)
end

assert(fns[1]() == 2)     ## 1 + 1
assert(fns[2]() == 6)     ## 2 + 4
assert(fns[3]() == 12)    ## 3 + 9

Two functions created on the same pass, on the other hand, do share the variable — which is what makes the reader/writer pair of the "Shared state" section below possible.

A function factory

func make_adder(x)
    func add(y)
        return x + y
    end
    return add
end

var add5  = make_adder(5)
var add10 = make_adder(10)

assert(add5(3)  == 8)
assert(add10(3) == 13)

Nested functions

A function declared inside another stays local — it is not added to the global environment.

func process(data)
    func helper(x)        ## visible inside process only
        return x * 2
    end
    return helper(data) + helper(data + 1)
end

assert(process(3) == 14)  ## 3*2 + 4*2

State shared between functions

func make_shared()
    var count = 0
    func inc()  count += 1  end
    func get()  return count  end
    return inc, get
end

var inc, get = make_shared()
inc()
inc()
inc()
assert(get() == 3)
print(get())  ## 3

Maps

A key→value dictionary. The literal syntax accepts strings, identifiers, or computed keys [expr]; at run time any value can serve as a key (nil, an integer, a float, a string, a bool, an array, a map, a function…).

Items are separated by a comma, and it is required between two of them — a newline does not stand in for it. A comma just before the closing brace is allowed, which keeps a multi-line literal easy to extend.

A keyword is a plain name in the two places where no keyword can be meant — a key in a literal and a field after a dot — so data whose keys read like keywords needs no detour: {end: 1, in: 2, class: "c"}, then m.end. The exceptions are true, false and nil, which carry a value: write {["true"]: 1} for the string, or {[true]: 1} for the boolean key itself.

Creating one

var empty = {}

var point = {"x": 10, "y": 20}

## keys without quotes
var config = {
    host:  "localhost",
    port:  8080,
    debug: false,
}

Literal keys and computed keys

A key written as an identifier, as a string, or in brackets around a string is the same literal key:

var a = {ref: 12}      ## the key is the string "ref"
var b = {"ref": 12}    ## the same
var c = {["ref"]: 12}  ## the same

In brackets, an expression is evaluated at run time and its value becomes the key:

var ref = "color"
var m = {[ref]: "red"}     ## the key is ref's value => "color"
assert(m["color"] == "red")
assert(m["ref"]     == nil)  ## the literal "ref" is NOT a key

## a computed key can be of any type
var n = {[1 + 1]: "two"}
assert(n[2] == "two")

The same rule holds for access: in brackets, a string literal names the key as it is, while a variable names its value. Reading, writing and compound assignment all behave the same:

var ref = "color"
var m = {}
m[ref]     = "red"              ## writes the "color" slot (ref's value)
m["size"] = 10                  ## writes the "size" slot (a literal)
assert(m["color"] == "red")   ## read back through a literal
assert(m.color     == "red")  ## or through a dot
m["size"] += 5
assert(m["size"] == 15)

Reading

Brackets
point["x"]  ## 10
point["z"]  ## nil
Dot (the same)
point.x  ## 10
point.z  ## nil

Writing

var point = {"x": 10, "y": 20}
point["z"] = 0   ## a new key
point.z = 5      ## the same

point["x"] += 1  ## compound through brackets
point.y *= 2     ## compound through a dot

assert(point.x == 11)
assert(point.y == 40)

Nested maps

var scene = {
    camera: {fov: 60, near: 0.1, far: 1000},
    light:  {x: 0, y: 10, z: 0, intensity: 1},
}

assert(scene["camera"]["fov"] == 60)

Keys of any type (through brackets)

var m = {}

m[nil]   = "nil key"
m[42]    = "int key"
m[3.14]  = "float key"
m[true]  = "bool key"

## 1 and 1.0 are the same key
m[1] = "one"
assert(m[1.0] == "one")

Copy semantics

Maps are shared by reference, with reference counting. Assigning a map to another variable does not clone it.
var a = {x: 1}
var b = a          ## b points at the same map
b.x = 99
assert(a.x == 99)  ## a changes too
A consequence: == compares maps by reference and not by content — {} == {} is 0. For equality by value, see Equality and comparison.

Iterating over a map

The form for k, v in m walks every entry of the map. The order is not guaranteed.

var scores = {Alice: 95, Bob: 82, Carol: 78}

for name, score in scores do
    printf("{} => {}", name, score)
end
## Alice => 95
## Bob => 82
## Carol => 78

Summing the values

var scores = {Alice: 95, Bob: 82, Carol: 78}
var total = 0
for k, v in scores do
    total += v
end
printf("average: {}", total / 3)

Inside a function

func sum_values(m)
    var s = 0
    for k, v in m do
        s += v
    end
    return s
end

var scores = {Alice: 95, Bob: 82, Carol: 78}
assert(sum_values(scores) == 255)

Enum

enum declares named constants. The result is a frozen map: it can be read, iterated and measured like any map, but every write is refused.

enum Tint RED, GREEN, BLUE end
print(Tint.RED, Tint.GREEN, Tint.BLUE)   ## 1 2 3

Numbering

An element with no value takes the counter, which starts at 1 and advances by one. An integer literal sets the value and restarts the counter just after it. Any other expression is accepted as a value but leaves the counter where it is — the compiler cannot evaluate a function call.

enum State IDLE = 0, WALK, JUMP = 10, FALL end
## 0, 1, 10, 11

enum Mixed A, B = "text", C end
## 1, "text", 2 — the string does not move the counter
A corollary: A = 1 + 1 is an expression and not a literal, so it does not move the counter even though it comes to two.

Values of any type

A value may be a number, a string, an object, an array or a function. Two elements with the same value are an alias, which is allowed; two elements with the same name are a compile error.

enum Palette RED = Color(1, 0, 0), GREEN = Color(0, 1, 0) end

Immutability

Writing into an enum fails. When the target is visibly the enumeration, the error comes at compile time and names the element; the indirect paths — an alias, a computed key — are stopped at run time.

Tint.RED = 5        ## a compile error: cannot modify enum 'Tint' element 'RED'

var m = Tint
m.RED = 5              ## a run-time error: cannot modify an enum
The freeze is shallow: it protects the enumeration, not what it holds. If an element is an array or an object, that array or object stays mutable — E.L[1] = 9 goes through. Freezing deeply would make immutable an object that may be referenced elsewhere. It protects the CONTENT and not the NAME: E = 5 replaces the enumeration, the name being an ordinary global — exactly like the name of a class.

The target

A simple name declares a global, as a class does: forward references work. A path writes into an existing map.

global cfg = {}
enum cfg.mode FULLSCREEN, WINDOWED end
print(cfg.mode.FULLSCREEN)      ## 1

References

ref x gives a function the means to read and write the variable x, instead of receiving a copy of it. That is what lets a module keep a variable up to date — the typical case being a checkbox bound to a setting.

global grid = true
ui.checkbox("Grid", ref grid)

func draw()
    if grid then          ## an ORDINARY read: ref changes nothing about using the variable
        drawGrid()
    end
end
The point to keep: the variable stays a variable. ref only passes on the right to write it; the code that uses it does not change.

Handling a reference you receive

A function that receives a reference reads it with get() and writes it with set(v).

func toggleIt(r)
    r.set(not r.get())
end

global active = false
toggleIt(ref active)
assert(active)

Accepted targets

A name — global or local — or a path of fields. The name must be declared: ref unknown is a compile error, which is the whole point compared with passing a name as a string.

ref counter           ## a global or a local
ref cfg.tiles         ## a field
ref cfg.render.shadows   ## a path of fields
ref t[1]              ## REFUSED: the path would be re-evaluated on every access

Two limits worth knowing

A reference taken on a variable local to a block stays readable after leaving the block, but writing reaches nothing any more: the variable is gone, and the reference has closed over a copy.

Every ref x evaluated creates two closures and an object. That is negligible when declaring a widget, and to be avoided in a tight loop.

Import

The import statement loads an Ollin file and makes its content available in the current program.

Paths are relative to the current script's directory. The .ol extension is added when it is missing.

A flat import

Every definition of the imported file becomes available directly in the current scope.

## utils.ol
func add(a, b)
    return a + b
end
var PI = 3.14159

## main.ol
import "utils"
print(add(2, 3))  ## 5
print(PI)         ## 3.14159

A modular import

With as name, every definition is gathered into a named map.

import "utils" as math
print(math.add(10, 20))  ## 30
print(math.PI)           ## 3.14159

Rules

  • Paths are resolved relative to the current script's directory, recursively for nested imports.
  • Circular imports are detected and ignored, through a shared cache.
  • A file imported twice is executed only once.

Classes

Ollin supports object orientation with single inheritance, an implicit constructor and meta-methods.

Declaration

class Animal
    func init(name, sound)
        self.name = name
        self.sound = sound
    end
    func speak()
        return self.name + " says " + self.sound
    end
    func __str()
        return "Animal(" + self.name + ")"
    end
end

var a = Animal("Rex", "Woof")
print(a)            ## Animal(Rex)   — the instance is printed through __str
print(a.speak())    ## Rex says Woof
  • func init(...) is the constructor; self is passed implicitly as the first parameter.
  • Every method receives self automatically.
  • func __str() defines how the instance prints: print(obj) and the concatenation "…" + obj both use it.

Instantiation

class Animal
    func init(name, sound)
        self.name = name
        self.sound = sound
    end
    func speak()
        return self.name + " says " + self.sound
    end
end
var a = Animal("Dog", "woof")
print(a.speak())   ## Dog says woof
print(a.name)      ## Dog

Static methods

A method prefixed with static belongs to the class and not to an instance: it does not receive self. It is called as Class.method(...), or on an instance, with no self injected. Handy for alternative constructors, or for utilities tied to the class.

static is refused on init and on every meta-method (__add, __str…): a constructor and an operator always receive the object, so a class-level one would have nothing to work on. Both refusals name the method.

class Vec
    func init(x, y)
        self.x = x
        self.y = y
    end
    static func zero()      ## no self: a factory tied to the class
        return Vec(0, 0)
    end
end
var o = Vec.zero()          ## called on the class
assert(o.x == 0 and o.y == 0)

class Animal
    func init(name, sound)
        self.name = name
        self.sound = sound
    end
    func speak()
        return self.name + " says " + self.sound

class Dog extends Animal
    func init(name)
        super.init(name, "woof")   ## calls the parent constructor
    end
    func fetch()
        return self.name + " fetches!"
    end
end

var d = Dog("Rex")
print(d.speak())   ## Rex says woof  (an inherited method)

A child with no func init inherits the parent's.

Equality and comparison

Bare maps and arrays compare by reference: a == b is true only when a and b name the same object in memory, never from their content. For a comparison by value, make it a class and define __eq.

## bare maps => compared by reference
print({x: 1} == {x: 1})            ## 0: the same content, but distinct objects
var m = {x: 1}
print(m == m)                      ## 1: the same reference

## an instance plus __eq => compared by value
class Point
    func init(x, y)
        self.x = x
        self.y = y
    end
    func __eq(other)
        return self.x == other.x and self.y == other.y
    end
end
print(Point(1, 2) == Point(1, 2))  ## 1: __eq compares the fields
print(Point(1, 2) == Point(3, 4))  ## 0
Two subtleties about __eq: it is looked up on the left operand only (when only the right one is an instance, the comparison stays by reference); and it is called even when both operands are the same instance — there is no identity short-circuit.

Graphics

The graphics module exposes raylib for real-time 2D rendering. It is available without any import. Rendering works on the desktop and in WASM.

The lifecycle

Three optional functions, called by the engine: setup() once at startup, then update(dt) and draw() on every frame.

## called ONCE after loading, before the loop
func setup()
    graphics.canvas(800, 600, "Title")
end

## called on every frame
func draw()
    graphics.clear(colors.BLACK)

    ## draw here

end

The three functions are independent: you may define just one. (You can also open the window at the script level rather than in setup.)

The mere presence of a draw() is enough to start a graphics session: if you do not call graphics.canvas(...), the engine creates a canvas of the default W×H size. Call graphics.canvas(w, h) only to choose another size or a title.

To keep the logic apart from the rendering, define update(dt) as well: the engine calls it before draw on every frame, with dt being the seconds elapsed since the previous frame. Multiplying the movements by dt makes the animation independent of the frame rate.

graphics.canvas(260, 140, "cycle")
var x = 0

## the logic: called BEFORE draw, dt = seconds since the previous frame
func update(dt)
    x = x + 120 * dt  ## 120 px per second, whatever the frame rate
    if x > 260 then x = 0 end
end

func draw()
    graphics.clear(colors.BLACK)
    graphics.fill(Color(1, 1, 1))
    graphics.circle(x, 70, 20)
end

You can also drive the loop explicitly with graphics.run(callback) if you would rather name your rendering function otherwise (update is still called first).

The persistent context and the blend modes

The drawing context is not cleared automatically between frames: that is for draw() to decide. With no call to graphics.clear(), the drawing accumulates from one frame to the next, giving trails. With an opaque colour, clear starts from a clean background; with a semi-transparent one (alpha < 1) it applies a fade — the previous content dims gradually towards that colour.

graphics.blendMode(mode) changes how the drawings combine with the content already there. The additive mode (blend.ADD), together with the persistent context and a slight fade, produces glows and luminous trails.

graphics.canvas(240, 160)
global t = 0
func draw()
    graphics.blendMode(blend.ADD)         ## additive blending (a glow)
    graphics.clear(Color(0, 0, 0, 0.08))  ## a slight fade → trails
    t = t + 0.05
    graphics.fill(Color(0.2, 0.5, 1))
    graphics.circle(120 + math.cos(t) * 80, 80 + math.sin(t * 1.3) * 50, 14)
end

3D

3D drawing shares the same loop and the same state as 2D. You place a camera, then draw shapes between graphics.begin3d(cam) and graphics.end3d(). As in 2D, fill and stroke drive the fill and the outline (the wireframe) — but the 3D wireframe's width is fixed at 1 px: graphics.strokeSize applies in 2D only. After end3d() a 2D HUD can be drawn on top, in the same frame.

The camera is an object (the Camera class, like Color): you create it once and then drive it through its methods. cam.setPos(x,y,z) sets the position, cam.lookAt(x,y,z) aims it at a target, cam.move(dx,dy,dz) moves the camera and its target together, keeping the aim, and cam.orbit(angle, radius [, height]) puts it in orbit around its target, the angle being in radians.

In 3D, call graphics.clear(an opaque colour) at the start of every frame: an opaque clear resets the depth buffer, which the depth test needs, as well as the colour.

Lighting and texture

Solid shapes (fill) are drawn by instancing, with a Blinn-Phong shader: every shape of one kind costs a single draw call, and each keeps a colour of its own. Lighting is opt-in: as long as no light is declared, the rendering is flat, in plain colour. As soon as a light exists, the faces are shaded according to their orientation.

Transforming 3D objects

The transformations (translate/rotate/scale) act on 3D solids as well. translate(x,y,z) places, rotate(deg, ax,ay,az) (or rotateX/Y/Z) orients, scale(...) resizes. They are cumulative inside the begin3d/end3d block; push()/pop() serve to isolate one object's transformation, by saving and restoring it.

func draw()
    graphics.clear(colors.BLACK)
    graphics.begin3d(cam)
        ## each cube in a push/pop block of its own
        graphics.push()
            graphics.translate(-3, 0, 0)
            graphics.rotateY(elapsedTime * 60)   ## turns around Y
            graphics.fill(colors.RED)
            graphics.cube(0, 0, 0,  2, 2, 2)
        graphics.pop()
        graphics.push()
            graphics.translate(3, 0, 0)
            graphics.rotate(elapsedTime * 90, 1, 1, 0)  ## an arbitrary axis
            graphics.fill(colors.SKYBLUE)
            graphics.cube(0, 0, 0,  2, 2, 2)
        graphics.pop()
    graphics.end3d()
end
## the camera is an object: created once, driven by its methods
global cam = graphics.camera(10, 6, 0,  0, 0, 0)

    cam.orbit(elapsedTime * 0.5, 10, 6)   ## orbits around the target (the angle in radians)
    graphics.noStroke()

        graphics.grid(10, 1)

    graphics.fontSize(22)
    graphics.text("Ollin 3D", 12, 12)   ## a 2D HUD on top
end

Voxel terrain: retained geometry and culling

For a world made of thousands of cubes, of the Minecraft kind, re-emitting every cube on every frame costs too much. Ollin offers retained geometry: the cubes of a "chunk" are baked once into GPU buffers, then redrawn in a single call per frame. Only the visible chunks are drawn, through a frustum test, and the distant ones are freed — bounded memory, and a potentially endless world.

NameDescription
graphics.beginChunk()Opens the recording: the graphics.cube/plane calls that follow are baked, that is recorded, rather than drawn
graphics.endChunk()Ends it and returns a handle to redraw on every frame: a map { id, idw, count, wcount }
graphics.drawChunk(handle)Redraws a baked chunk's opaque part in a single call, inside begin3d
graphics.drawChunkAlpha(handle)Draws the transparent part (instances whose fill alpha is < 1, water for instance). To be called AFTER all the opaque geometry
graphics.freeChunk(handle)Frees a (distant) chunk's GPU buffers, giving the memory back
graphics.inFrustum(x,y,z [, radius])Is the sphere (centre, radius) visible to the camera, at least in part? → 1/0. Used for culling by chunk; to be called inside begin3d

A chunk is split into two groups according to the fill alpha: opaque (drawChunk) and transparent (drawChunkAlpha). The order is mandatory: draw ALL the opaque geometry, THEN all the transparency — the alpha blending is wrong otherwise.

Tile atlas (a texture per face)

To texture a terrain without one draw call per material, use an atlas: a single image laid out as a grid of tiles. Each cube carries a triplet of tiles (top / side / bottom); the shader picks according to the face — grass on top, earth on the sides. The atlas can be generated in Ollin with the image module, pixel by pixel, or loaded from an image.

NameDescription
graphics.tileset(img, cols, rows)Declares the tile atlas (a cols×rows grid, NEAREST filtering, so the pixels stay crisp)
graphics.tile(t)The same tile t on the next cube's six faces (a state, like fill); -1 means none, giving plain colour
graphics.tiles(top, side, bottom)Distinct tiles per face, as indices into the atlas
graphics.tileAnim(t)Names a tile whose UV scrolls over time, for rippling water
graphics.corners(a, b, c, d)The heights of the four corners of the next cube's top (a state), as a fraction of its height: (-x,-z), (+x,-z), (-x,+z), (+x,+z). With no argument the top is flat

A cube with deformed corners is still an instanced cube: the displacement happens in the vertex shader, so it costs no draw call. Two neighbouring cubes giving the same value to the corner they share form a continuous surface — enough to let a terrain follow its unrounded height instead of a step. Keep it for renderings that want it: the Voxel world example keeps all its cubes identical.

With an atlas active, give every cube of the chunk a tile (tile/tiles): a cube with no tile would sample tile 0 instead of a plain colour.
## a voxel chunk: baked ONCE in setup(), redrawn in one call per frame
global cam = graphics.camera(26, 20, 26,  8, 3, 8)
global chunk = nil

func setup()
    graphics.canvas(W, H, "voxel")
    graphics.ambient(0.5)
    graphics.light("dir", -0.5, -1, -0.35)
    graphics.beginChunk()                 ## the baking starts
    graphics.fill(colors.WHITE)
    for x = 0, 15 do
        for z = 0, 15 do
            var h = math.floor(math.noise(x * 0.12, z * 0.12) * 6) + 1
            for y = 0, h do
                graphics.cube(x, y, z,  1, 1, 1)
            end
        end
    end
    chunk = graphics.endChunk()           ## a lasting handle
end

func draw()
    graphics.clear(Color(0.55, 0.8, 0.95))
    cam.orbit(elapsedTime * 0.3, 26, 20)
    graphics.begin3d(cam)
        if graphics.inFrustum(8, 3, 8, 20) then   ## drawn only when visible
            graphics.drawChunk(chunk)                 ## one call draws the whole chunk
        end
    graphics.end3d()
end

The touch module

It follows several fingers at once, each by a stable identifier. That is what two notes held together, a two-thumb gamepad or a pinch need — where mouse reports a single point.

## One note per finger: the identifier is the key, so several sound together.
global under = {}

func touch.began(id, x, y)
    under[id] = keyAt(x, y)
    sound.tone(sound.note(notes[under[id]]), 0.5).play()
end

func touch.ended(id, x, y)
    under[id] = nil
end

Zoom with two fingers — pinch

A pinch is the only zoom a phone has: mouse.scrolled reports a wheel, which no touch screen owns. touch.pinch fills that gap, and the engine derives it from two contacts so that no script has to.

scale is a ratio between two frames, not a distance: above 1 the fingers are spreading, below 1 they are closing. A ratio composes by multiplication, which is exactly what a zoom needs — and it leaves the script no state to keep. (cx, cy) is the midpoint of the two contacts, for a zoom centred on the gesture rather than on the screen.

## One zoom, two gestures: only the factor differs.
func zoomBy(factor)
    size = math.clamp(size * factor, 3, 40)
end

func mouse.scrolled(x, y, dx, dy)
    zoomBy(1.0 - dy * 0.1)      ## a wheel notch is a step
end

func touch.pinch(scale, cx, cy)
    zoomBy(1.0 / scale)          ## spreading brings the scene closer
end

Three things the engine settles, and which a hand-written version gets wrong: the gesture is identified by the pair of contacts, so the graphics layer swapping its two entries between frames changes nothing; replacing one finger of the pinch by another re-arms the reference distance instead of reporting a jump; and two fingers pressed on the same point are dropped rather than divided by, which would give a scale of several hundred. Fingers held still call nothing at all.

A pinch is not a drag. While two fingers are down the system still emulates the mouse with one of them, so a script that orbits on mouse.moved must guard it with touch.count() > 1 — otherwise the scene spins as one zooms. The Isometric camera example does exactly that.
The mouse callbacks are not suppressed: under a single finger the system emulates the mouse, so a script declaring both families receives the gesture twice. Write each path so that a duplicate has no effect, or listen to one family only.

What to know

  • Up to eight contacts are followed. A ninth finger is ignored, as the graphics engine itself ignores it.
  • On a computer a mouse has a single pointer: touch.count() is always zero there, and mouse is what serves.
  • The tracking is rebuilt by the engine: the graphics layer gives only a snapshot of the contacts on each frame, without saying which has just appeared. It is the comparison from one frame to the next that produces the three callbacks.
  • The identifier stays the same from the start of a gesture to its end, but it is reused afterwards: do not keep it beyond ended.
  • A web page must set touch-action: none on its canvas, otherwise two fingers set off the browser's zoom instead of reaching the program. The site's views already do so.

The ui module

Buttons, checkboxes and sliders drawn by the engine, stacked in the top-right corner of the drawing area. There is no dependency on the browser: the same code runs natively, under a virtual display, and in the playground.

A widget is declared once — at the file level or in setup(). The engine draws it and tests it on every frame: there is nothing to call inside draw().

The interface is closed at startup: it shrinks to a three-bar handle in the corner, so as not to hide the scene. A click on it unfolds the menu on display, whose header row carries the handle and the menu's title; a click on that header closes it again.

global grid = true
global speed = nil   ## the slider initialises it to its default

func resetAll()
    t = 0
end

ui.button("Reset", resetAll)
ui.checkbox("Grid", ref grid)
ui.slider("Speed", ref speed, 0.25, 3, 1.0)

func draw()
    if grid then       ## an ORDINARY read of the bound variable
        drawGrid()
    end
end

Lists

A list chooses one item among several. Its source is an array, a map or an enum, and the display rule is that of for … in: an array gives its values, a map or an enum its keys. The bound variable receives exactly what is shown — the value for an array, the key for a map or an enum.

global shapes = ["circle", "square", "triangle"]
enum Dir
    clockwise,
    counterClockwise
end
global shape = nil      ## the list initialises it to the first item
global dir = nil

func setup()

    menu.list("Shape", shapes, ref shape)        ## shape receives "circle", "square"…
    menu.list("Direction", Dir, ref dir, onDir)   ## dir receives "clockwise" or "counterClockwise"
    ui.show(menu)

  • The row shows the label and the item chosen; a click unfolds the list, where the current item carries a round mark. Choosing closes the list and returns to the menu. element.open() unfolds it from the program, as it does for a sub-menu.
  • The selection is always defined: a variable at nil is initialised to the first item. A value already set is kept.
  • The items are read again on every opening: changing the source between two openings shows, and costs nothing per frame.
  • The order is fixed, since a map has none: an enum is sorted by value — hence in declaration order — and an ordinary map by label. An array keeps the order of its indices.
  • onChange receives the item chosen.

What to know

  • The interface's size is proportional to the drawing area's height, so it is readable on a desktop screen as much as on a phone, whose canvas counts several pixels per display pixel.
  • The memory and frames-per-second overlay sits in the bottom-right corner, opposite the stack.
  • The labels use the engine's default font (see graphics.font), not the one the script has chosen: the interface keeps its appearance whatever the program does.
  • Removing a menu you are inside moves the display up to the first parent menu still present. Using a removed handle raises an explicit error.
  • A slider gives an integer value when its bounds and its starting value are integers, and a float otherwise: ui.slider("Factor", ref f, 0, 1, 0.5) therefore adjusts a float despite its integer bounds.
  • The bound variable is the only source of truth: the slider reads its value on every frame, so the program can write it itself and the display follows. A value out of range is clamped for the display, without writing to the variable.
  • ref accepts a path of fields: ui.checkbox("Grid", ref config.grid) allows every setting to be gathered into one object rather than scattered across global variables (see the "Interface (ui)" example).
  • A checkbox's variable must be reachable: a global, or an object's field. A variable local to a function makes no sense here, since it is gone before the first click.
  • With no graphics area — a command-line run with no window — declaring a widget does nothing, but the arguments are checked all the same.

It moves an object's field — or a variable passed by ref — from its current value towards a target, over a duration, along a curve. The engine advances the animations on every frame: you declare, and there is nothing to call inside draw(). The drawing only reads the animated fields.

An animation is played in passes. repeat([count] [, backAndForth]) sets how many: with no count the repetition is endless; the second parameter adds the backward reading to the plan.

.repeat(nil, true)forward and back, endlessly

The count is recognised by its position, hence the nil: true is 1 in Ollin, so repeat(true) could not be told from repeat(1).

The round trip applies to the whole set of passes, not to each one: repeat(2, true) plays both forward passes then both backward ones. To alternate every time, compose two calls — repeat(nil, true).repeat(2) gives two round trips. That is the difference from GSAP or Phaser, where yoyo reverses every repetition.

Every pass replays the whole animation in its own direction: between two forward passes the value therefore returns to the start, and between two backward ones it sets off again from the target. The bounds are fixed at the first start — writing into the object mid-animation does not redefine the next pass's start. progress() covers the whole plan (a plan of four passes gives 0.5 halfway through the second); when endless, it gives the current pass's progress.

Take care: an endless repetition never finishes by itself, and holds on to the animated object until cancel() — or tween.cancelAll() — has been called.

## A pulse: the radius grows then comes back, endlessly.
tween.to(ball, {r: 40}, 0.6, "easeInOutQuad").repeat(nil, true)

## Three flashes, ending on the starting colour.
tween.to(ball, {tint: Color(1, 0.3, 0.2)}, 0.2).repeat(nil, true).repeat(3)

Chaining: tween.sequence

tween.sequence(object, [steps]) plays a series of animations one after another. Each step is a map, and the time key is called delay in both roles: the animation's duration when the step carries to, and a plain wait when it does not.

KeyRole
tothe fields aimed at, as in tween.to: {y: 300}
delaythe step's duration in seconds — or a wait when the step has no to
curvea curve name or a function, belonging to this step
targetanother object to animate; without it, the object passed as the first argument

Any other key is refused, with the list of those allowed: a misguessed duration or easing fails outright instead of being ignored in silence.

A step's starting value is the one the previous step left, read when it starts — two consecutive steps therefore join with no jump. repeat applies to the whole series, and its round trip replays it backwards, each step reversed. progress() runs over the whole series, in time: steps of unequal duration still give a steady progression.

tween.sequence(ball, [
    {to: {y: 300}, delay: 0.4, curve: "easeOutQuad"},
    {to: {y: 100}, delay: 0.6, curve: "easeInQuad"},
    {delay: 0.2},                                ## a pause
    {target: shadow, to: {a: 0}, delay: 0.5},   ## another object
])

The "Animated sequence (tween)" example bounces a ball in five steps: the fall, the squash on impact, the release, the rise and a pause. It is the unequal durations — a tenth of a second for the squash against half a second for the fall — that give the ball its weight.

The handle returned is an ordinary tween's: pause(), cancel(), isDone(), delay() and repeat() all apply as they are. Overwriting one of the animated fields with another tween cancels the sequence, as it does for tween.to.

## The drawing reads fields; time is none of its business.
global ball = {x: 0, r: 20, tint: Color(0.3, 0.7, 1)}

func setup()
    graphics.canvas(W, H)
    ## Several fields at once, a COLOUR among them, interpolated component by component.
    tween.to(ball, {x: W * 0.8, r: 60, tint: Color(1, 0.45, 0.2)}, 1.2, "easeOutBack")
    ## Then a return, 0.3 s after the first has finished.
    tween.to(ball, {r: 20}, 0.8, "easeInQuad").delay(1.5)
end

func draw()
    graphics.clear(colors.BLACK)
    graphics.fill(ball.tint)
    graphics.circle(ball.x, CY, ball.r)
end

Curves

linear, then the easeIn / easeOut / easeInOut families in their Quad, Cubic, Sine, Expo and Back flavours, plus easeOutElastic and easeOutBounce. The default is easeInOutQuad. A function can also fill the role — it receives the progress over [0;1] and returns the corrected progress:

tween.to(obj, {x: 100}, 1, func(p) return p * p * p end)
The last two arguments are recognised by their type: a string or a function gives the curve, and the function after that is the completion callback. There is no order to remember.

tween.curves() lends itself directly to a list of the ui module: the source is the engine's catalogue, and the bound variable receives the name chosen. That is what the "Animations (tween)" example does.

menu.list("Curve", tween.curves(), ref config.curve, onCurve)

What to know

  • The starting value is read when the animation starts, not when it is declared: with a delay, the tween sets off from the value the field has at that moment.
  • Declaring a tween on a field already animated cancels the previous one: two animations never fight over the same value. Two distinct refs on the same variable are not recognised as the same, however — the language does not allow them to be compared.
  • When the starting value and the target are integers, the value stays an integer throughout.
  • A target value may be a class instance: the numeric fields common to both are interpolated one by one, which covers Color as much as a Vec2 of your own. The tween writes into the instance; it does not replace it.
  • The final value written is the exact target: an overshooting curve does not quite give 1 at the end, and rounding would leave 0.999.
  • The completion callback may declare further tweens — enough to chain steps — or cancel everything.

The audio and sound modules

Sound splits in two: audio is the session — the device, the master volume, the pause — and sound is what sounds. No file is needed: every sound on this page is computed.

sound offers two kinds of object, and the difference is not cosmetic:

  • a living oscillator, whose frequency is moved while it sounds — a siren, a vibrato driven by the mouse;
  • a frozen buffer, computed once then triggered — a beep, a note, a rhythmic loop.

An oscillator

global siren = sound.saw(220)

func setup()
    graphics.canvas(W, H)
    siren.volume(0.3).start()
end

func draw()
    ## The frequency follows the mouse: that is the whole point of a living oscillator.
    siren.freq(200 + 600 * mouse.x / W)
end
FactoryRole
sound.osc(freq [, shape])an oscillator, the shape given by its name
sound.sine / square / saw / triangleshorthands: the shape is in the name, so it is never misspelt
sound.noise()white noise (a frequency does not apply)

An oscillator's methods: start, stop, isPlaying, freq, volume, pan, shape, envelope, trigger, release, free. As elsewhere in the engine, with no argument they read, and with one they write and return the object: o.freq(440).volume(0.2).pan(-1).

An envelope, for playing notes

An oscillator merely started and stopped gives a flat sound. The ADSR envelope gives it an attack, a decay, a sustain and a release — which is what tells a note from a test signal.

global voice = sound.triangle(440).envelope(0.01, 0.08, 0.5, 0.25)

func mouse.pressed(x, y)
    ## With a duration, the release starts by itself when the time comes.
    voice.freq(sound.note("C4")).trigger(0.2)
end

trigger() with no duration holds the note until release(). A released note frees its voice, so a program can trigger them indefinitely. When you no longer need an oscillator, free() gives it back to the engine: the note finishes dying away, then the voice becomes available again — which is what allows one per finger placed, rather than pre-allocating them. The handle is then stale, and reusing it raises an explicit error. Pitches are written in plain text: sound.note("C#4") gives 277.18 Hz, and a note name is accepted anywhere a frequency is.

A computed buffer

sound.tone(freq, duration [, shape]) samples a waveform; sound.generate(duration, formula) samples your formula, which receives the time in seconds and returns an amplitude in [-1;1].

global beep = sound.tone(880, 0.12, "square").envelope(0.005, 0.02, 0.6, 0.05)

## A bell: a sine that dies away on its own.
global bell = sound.generate(1.2, func(t)
    return math.sin(t * 6.283 * 660) * math.exp(-t * 3)
end)

beep.play()
bell.volume(0.4).play()

The formula is evaluated once only, at construction — never during playback. A buffer's methods: play, stop, isPlaying, volume, pan, rate, loop, envelope, plus three getters that read the computed sound.

GetterReturns
duration()the buffer's duration, in seconds
peak()the greatest amplitude, in absolute value
sample(t)the sample at time t; zero outside the buffer

rate changes the playback speed, hence the pitch and the duration, like a record played faster: it is not a transposition.

The session

CallRole
audio.volume([v])the master volume, clamped to [0;1]
audio.pause() / resume()suspends the sound's progress, and not merely its volume
audio.isPaused() / isReady()the state of the pause, and of the device

A browser refuses to make a sound before an interaction. The engine therefore opens the device on the first click or the first key, and there is nothing to write for that. A sound asked for in setup(), on the other hand, will only be heard after that first gesture.

What to know

  • Computing the waves does not depend on graphics: a buffer can be built and measured with no sound card at all, which the engine's test suite makes use of.
  • Sixteen oscillators and thirty-two sounds coexist. When the table is full, the oldest stopped one is recycled — a sound that is playing is never stolen — and its old object becomes invalid.
  • No Ollin code runs in the audio path: a generate's formula is sampled in advance, and an oscillator's shape is computed by the engine. That is what keeps the crackles away.
  • Natively, the sound carries on even while a computation keeps the virtual machine busy; in the browser the mixing shares the page's thread, so a very heavy frame can be heard.
  • Out of scope for now: loading files, effects, recording and spatialisation.

The date module

The calendar, which time() alone cannot give: it returns the seconds since the Unix epoch, and turning those into a day and an hour means leap years, month lengths and above all a time zone with its summer time. Available without any import. Both functions return a plain map.

FunctionDescription
date.now([t])The parts of the local time; with no argument, of this instant. t is a number of seconds since the epoch, as time() returns it — its decimals become the milliseconds

yearthe full year, 2026 and not 126

## the week-end, since Monday is 1

    print("day off")

There is no formatting function: interpolation does the job, and it leaves the layout to whoever writes it — "{d.hour}:{d.minute}". Nor is there any arithmetic on dates: add seconds to the number time() gives you, then decode.

The image module

The image module loads textures from disk, or from base64 data, and creates render textures for off-screen rendering. Available without any import.

graphics.canvas() must be called before any image operation — the GL context has to exist.

Loading an image

graphics.canvas(240, 140, "image.load")
var tex = image.load("assets/smiley.png")  ## a handle {id, width, height} — a served resource

func draw()
    graphics.clear(Color(0.1, 0.12, 0.2))
    graphics.sprite(tex, 20, 40, 64, 64)   ## 64×64
    graphics.sprite(tex, 120, 25, 96, 96)  ## resized
end
image.load(name) resolves the name like this: natively, a file on disk; in WASM, first an image added through the "Images" button, otherwise a resource served by the site (same origin, fetched automatically — image.load("assets/logo.png"), relative to the page). In both cases the file is looked for beside the program first, then under the name as written: a script kept in its own directory names its data without repeating that directory, and it no longer matters which directory the program was started from. For an image embedded in the script, portable anywhere and needing no network, use image.loadData("png", base64) — see the playground's "Image (loadData)" example.

Render texture (off-screen drawing)

graphics.canvas(180, 180, "render texture")
var rt = image.create(120, 120)  ## a 120×120 render texture

image.beginDraw(rt)             ## we draw INTO the texture, once
    graphics.clear(Color(0.1, 0.1, 0.15))
    graphics.fill(colors.RED)
    graphics.circle(60, 60, 50)
image.endDraw()

func draw()                      ## then show it like a sprite
    graphics.clear(colors.BLACK)
    graphics.sprite(rt, 30, 30)
end
